# NODI 모바일 UX/UI 개선 명세서

**권장 파일명:** `NODI_Mobile_UI_Improvement_Spec.md`  
**버전:** 2.0  
**기준:** NODI 모바일 시안 16개 화면  
**목표:** 시각적 완성도 향상, 정보 가독성 개선, 모바일 조작성 강화, 상태 정보의 신뢰성 확보

---

## 1. 개선 방향

### 1.1 디자인 원칙

NODI의 기존 디자인 방향인 **Soft Clarity**를 유지한다.

- 브랜드 로고와 블루·퍼플 아이덴티티 유지
- 기존 3개 하단 탭 구조 유지
- 카드 중심의 부드러운 UI 유지
- iOS 네이티브 앱처럼 자연스러운 조작 경험 제공
- 중요한 정보는 강조하고, 보조 설명은 축약
- 상태를 색상뿐 아니라 텍스트와 아이콘으로 함께 전달
- 실제 구현되지 않은 기능은 성공한 것처럼 표현하지 않음

### 1.2 이번 개선에서 하지 않을 것

- 브랜드 컬러 전면 변경
- 전체 화면 구조의 불필요한 재설계
- 기능 추가를 위한 기능 추가
- 기존 사용자 흐름의 대규모 변경
- 검증되지 않은 AI 추천 점수 또는 성과 수치 표시

## 2. 공통 디자인 시스템

### 2.1 컬러 토큰

```css
:root {
  --color-primary: #3654D4;
  --color-primary-hover: #2E49BC;
  --color-primary-soft: #E9EEFF;

  --color-accent-purple: #8C75F5;

  --color-text-primary: #18243A;
  --color-text-secondary: #53637D;
  --color-text-tertiary: #718098;

  --color-background: #F5F7FB;
  --color-surface: #FFFFFF;
  --color-surface-muted: #F1F4F9;

  --color-border: #D7DFEB;
  --color-divider: #E7ECF3;

  --color-success: #137B57;
  --color-success-bg: #E8F7EF;

  --color-warning: #925500;
  --color-warning-bg: #FFF3DC;

  --color-danger: #B52E3A;
  --color-danger-bg: #FDECEE;

  --color-disabled-bg: #DFE5EF;
  --color-disabled-text: #65748D;
}
```

**적용 기준**

- Primary Blue: 주요 CTA, 선택된 옵션, 현재 진행 단계
- Purple: 브랜드 장식 요소에 제한적으로 사용
- Green: 실제 충족 또는 완료된 상태
- Amber: 확인 필요, 응답 대기, 부분 실패
- Red: 오류, 충돌, 불가능, 필수 조건 미충족
- Gray: 보조 정보, 미선택, 비활성

색상은 제안 토큰이며 최종 적용 전 기존 브랜드 색상과 대비 검증이 필요하다.

### 2.2 타이포그래피

| UI 요소 | 크기 | 굵기 | 행간 |
|---|---:|---|---:|
| 페이지 제목 | 24px | 700 | 32px |
| 바텀시트 제목 | 22px | 700 | 30px |
| 모달 제목 | 22px | 700 | 30px |
| 섹션 제목 | 18px | 650 | 26px |
| 카드 핵심 시간 | 24px | 700 | 32px |
| 카드 제목 | 18px | 650 | 26px |
| 기본 본문 | 16px | 400 | 24px |
| 보조 본문 | 14px | 400 | 21px |
| 캡션 | 12px | 500 | 18px |
| 주요 버튼 | 16px | 650 | 24px |

**개선 규칙**

1. 하나의 카드에서 가장 큰 글씨는 한 요소에만 사용한다.
2. 시간 추천 카드에서는 시간을 가장 크게 표시한다.
3. 상태 배지는 제목보다 작게 표시한다.
4. 긴 설명은 기본 14px로 줄이고 필요한 경우 펼치기 기능을 제공한다.
5. 시스템 글자 크기 확대 시 텍스트 잘림을 방지한다.
6. 숫자와 시간은 가능한 한 일관된 숫자 폭을 사용한다.

### 2.3 간격 시스템

기본 간격 단위는 4px로 한다.

| 항목 | 권장 값 |
|---|---:|
| 화면 좌우 여백 | 20px |
| 상단 제목과 본문 간격 | 24px |
| 섹션 간격 | 32px |
| 카드 간격 | 16px |
| 카드 내부 패딩 | 20px |
| 카드 제목과 내용 간격 | 12px |
| 폼 라벨과 입력 필드 간격 | 8px |
| 옵션 버튼 간격 | 8~12px |
| 하단 CTA 좌우 여백 | 20px |
| 하단 CTA 위 여백 | 16px |

**주의:** 모든 요소에 동일한 간격을 적용하지 않는다. 정보가 하나의 그룹인지, 서로 다른 그룹인지에 따라 간격을 구분한다.

### 2.4 Radius

```css
:root {
  --radius-input: 14px;
  --radius-button: 16px;
  --radius-card: 20px;
  --radius-sheet: 28px;
  --radius-pill: 999px;
}
```

- 입력 필드: 14px
- 일반 버튼: 16px
- 카드: 20px
- 바텀시트 상단: 28px
- 상태 배지 및 선택 칩: pill

### 2.5 그림자와 테두리

- 기본 카드는 얇은 테두리를 우선 사용한다.
- 그림자는 바텀 내비게이션, 떠 있는 패널 등 계층 구분이 필요한 곳에만 적용한다.
- 모든 카드에 강한 그림자를 반복하지 않는다.
- 선택된 카드는 배경색 또는 테두리로 명확히 구분한다.

```css
.card {
  background: var(--color-surface);
  border: 1px solid var(--color-divider);
  border-radius: var(--radius-card);
}

.card[data-selected="true"] {
  border: 2px solid var(--color-primary);
  background: #F7F9FF;
}
```

## 3. 공통 컴포넌트 개선

### 3.1 상단 헤더

**현재 문제**

- 화면마다 제목 크기와 상단 여백이 다르게 느껴짐
- 뒤로 가기, 닫기, 사용자 프로필 등의 위치가 일정하지 않음

**개선안**

- 헤더 높이: 기본 56px
- 뒤로 가기 버튼 터치 영역: 최소 44×44px
- 제목은 한 줄을 기본으로 하되 긴 제목은 축약 또는 줄바꿈 정책 적용
- 뒤로 가기와 닫기를 같은 의미로 사용하지 않음
- 편집 화면을 닫을 때 변경사항이 있다면 저장 여부 확인

### 3.2 진행 단계 표시

대상: 01, 05, 06, 07번

**현재 문제**

- 진행 바는 보이지만 각 단계의 의미가 충분히 드러나지 않음
- `다음: ...` 문구와 현재 단계 표시가 시각적으로 분산됨

**개선안**

상단 구조를 다음 순서로 통일한다.

1. 화면 제목
2. 5단계 진행 바
3. `3/5 · 조율 현황`
4. 보조 문구 `다음: 추천 시간`

**구현 기준**

- 완료 단계: Primary Blue
- 현재 단계: Primary Blue 또는 강조 상태
- 미완료 단계: Neutral Gray
- 진행 바와 단계명 사이: 12px
- 진행 상태는 스크린리더에도 텍스트로 전달

### 3.3 주요 CTA

**현재 문제**

- 고정 CTA와 본문이 겹치는 화면이 있음
- 비활성 버튼의 사유가 충분히 명확하지 않음
- 버튼 높이와 하단 여백이 화면마다 다름

**개선안**

- 주요 버튼 높이: 56px
- 보조 버튼 높이: 52px
- 버튼 텍스트: 16px Semibold
- 비활성 버튼에도 비활성 사유를 인접한 위치에 표시
- 로딩 시 버튼 너비와 높이를 유지
- 중복 제출 방지
- 주요 CTA는 화면당 원칙적으로 하나만 사용

**예시**

- 비활성: `후보를 선택해 주세요`
- 선택 후: `이 시간으로 계속`
- 처리 중: `회의를 저장하는 중...`
- 성공 후: 완료 화면으로 이동

### 3.4 상태 배지

배지의 의미를 다음과 같이 표준화한다.

| 상태 | 배지 문구 | 색상 |
|---|---|---|
| NODI 내부 저장 완료 | NODI 확정됨 | Green |
| 일정 필수 조건 충족 | 필수 조건 충족 | Green |
| 참석 가능 응답 | 가능 응답 | Green |
| 응답 필요 | 응답 필요 | Amber |
| 응답 대기 | 응답 대기 | Gray/Amber |
| 다시 확인 필요 | 재확인 필요 | Red |
| 캘린더 충돌 | 일정 충돌 | Red |
| 외부 알림 일부 실패 | 일부 실패 | Amber |
| 외부 캘린더 미연결 | 연결 안 됨 | Gray |

**중요:** `필수 조건 충족`은 참석 수락이나 외부 캘린더 등록 완료를 뜻하지 않는다.

### 3.5 바텀시트

대상: 02, 03, 04번

**개선안**

- 최대 높이: 화면의 약 90%
- 상단 드래그 핸들: 36×5px
- 상단 제목 영역 고정
- 본문만 스크롤
- 하단 CTA 영역 고정
- 키보드가 열리면 본문 높이 재계산
- 닫기 버튼은 최소 44×44px
- 변경사항이 있을 때 닫기 시 확인 모달 표시

### 3.6 하단 탭바

탭 구성은 유지한다.

- 회의 잡기
- 내 회의
- 받은 요청

**개선안**

- 탭 아이콘 크기: 22~24px
- 라벨 크기: 12~13px
- 선택 탭은 아이콘과 라벨을 모두 강조
- 알림 배지는 실제 미처리 건수 기준
- 숫자가 99를 넘으면 `99+` 표시
- 집중 입력 단계에서는 탭바 숨김
- 일반 목록 화면에서는 탭바 노출
- iOS 홈 인디케이터와 충돌하지 않도록 safe area 확보

## 4. 화면별 상세 UI 개선안

## 4.1 화면 01 — AI 조건 확인

### 발견 문제

1. 대화 카드가 전체적으로 커서 조건 확인 카드가 아래로 밀림
2. AI가 추출한 날짜와 원문 날짜의 관계가 직관적이지 않음
3. `AI 해석` 라벨이 반복되어 정보 밀도가 높음
4. 하단 입력창과 탭바 사이가 복잡함

### 개선안

**A. 대화 영역**

- AI 메시지 패딩: 16px
- 사용자 메시지 패딩: 16px
- 메시지 최대 너비: 화면의 84~88%
- 아바타 크기: 28~32px
- 메시지 간 간격: 12px
- 긴 AI 안내 문구는 2문장 이내로 축약

**B. 조건 확인 카드**

카드 제목:

`회의 조건을 이렇게 이해했어요`

정보 표시 순서:

1. 회의 제목
2. 회의 길이
3. 날짜 또는 기간
4. 선호 시간대
5. 미확정 조건

각 행은 다음 구조를 사용한다.

`라벨 | 해석된 값 | 수정 아이콘`

`AI 해석`은 각 행마다 반복하지 않고 카드 상단에 한 번만 표시한다.

**C. 날짜 해석**

예시:

- 입력: `다음 주 화요일`
- 해석: `11월 24일 (화)`
- 기준일: `11월 16일 (월)`

기준일과 해석 결과를 명확히 분리한다.

**D. CTA**

- 조건이 유효하면 `조건 확인하고 계속`
- 미확정 조건이 있으면 `조건 수정하기`
- 조건 확인 카드의 마지막 항목이 입력창 뒤에 가려지지 않도록 처리

### 완료 기준

- 사용자가 AI 해석 결과를 한 화면에서 확인할 수 있다.
- 날짜 해석 기준을 이해할 수 있다.
- 각 조건을 직접 수정할 수 있다.

## 4.2 화면 02 — 회의 조건 수정

### 발견 문제

- 회의 길이 옵션이 두 줄로 배치되어 높이가 큼
- 날짜 선택 영역이 복잡함
- 하단 시간대 설명이 고정 CTA에 가까움

### 개선안

**A. 회의 길이**

- 30분 / 45분 / 60분 / 90분 / 120분
- 동일한 높이의 선택 버튼 사용
- 버튼 높이: 48px
- 버튼 간격: 8px
- `1시간` 대신 `60분`처럼 단위 표현 통일 권장

**B. 날짜**

탭:

- 특정 날짜
- 기간

특정 날짜:

- 주간 날짜 선택
- 선택 날짜를 요약 카드에 표시

기간:

- 시작일과 종료일 선택
- 기간의 시작·종료가 명확히 보이도록 표시

**C. 선호 시간대**

- 오전
- 오후
- 상관없음

선택 버튼 3개를 한 줄에 배치한다.

보조 설명:

`오전 9–12시 · 오후 13–18시`

**D. 저장 버튼**

- 변경 전: `변경된 내용이 없어요`
- 변경 후: `변경사항 저장`
- 저장 후 조건 확인 화면으로 복귀

### 완료 기준

- 선택 상태가 명확하다.
- 날짜와 기간을 혼동하지 않는다.
- 마지막 필드까지 스크롤할 수 있다.

## 4.3 화면 03 — 참석자 선택

### 발견 문제

- 선택된 참석자 칩이 여러 줄을 차지함
- 검색과 추천 목록 사이의 설명이 길다
- 최근 회의 참여자와 검색 결과의 구분이 약하다
- 선택된 사람의 식별 정보가 목록에 따라 다르게 표시됨

### 개선안

**A. 상단 구조**

1. 제목: `참석자 선택`
2. 선택 수: `3명 선택`
3. 검색 필드
4. 팀 필터
5. 선택된 참석자 요약
6. 최근 함께 회의한 사람
7. 전체 검색 결과

**B. 선택된 참석자**

선택 인원이 3명 이하라면 칩 노출.

4명 이상이면:

`선택된 참석자 4명 보기`

형태로 접을 수 있게 한다.

**C. 참석자 행**

- 체크박스: 24px
- 아바타: 40px
- 이름: 16px Semibold
- 소속 및 보조 정보: 14px
- 행 높이: 최소 64px
- 선택된 행 배경: Primary Soft

**D. 동명이인**

동명이인인 경우:

`김서안 · 디자인팀`

추가 식별이 필요하면 이메일 노출.

**E. 하단 CTA**

`3명 선택 · 다음`

### 완료 기준

- 검색과 선택을 동시에 수행할 수 있다.
- 선택 인원이 많아져도 목록 탐색이 가능하다.
- 동명이인을 구분할 수 있다.

## 4.4 화면 04 — 일정 필수 설정

### 발견 문제

- 정책 설명이 길다
- 필수 참석자 지정과 회의 성립 정책이 한 화면에 밀집됨
- 토글과 선택 카드가 모두 강하게 강조됨

### 완료 기준

- 다시 응답해야 하는 이유를 이해한다.
- 기존 응답을 불필요하게 반복하지 않는다.

## 5. 반응형 및 모바일 동작 기준

### 5.1 화면 크기

검증 대상:

- 320px 너비의 작은 모바일
- 375px 너비의 일반 모바일
- 390~430px 너비의 큰 모바일
- 모바일 가로 모드
- 태블릿 너비

### 5.2 레이아웃

```css
.mobile-page {
  min-height: 100dvh;
  background: var(--color-background);
}

.page-content {
  padding-inline: 20px;
  padding-bottom: calc(
    var(--bottom-action-height, 0px) +
    env(safe-area-inset-bottom) +
    24px
  );
}

.bottom-action {
  position: fixed;
  left: 0;
  right: 0;
  bottom: 0;
  padding: 16px 20px calc(16px + env(safe-area-inset-bottom));
  background: var(--color-background);
}
```

실제 구현에서는 페이지별 하단 CTA와 탭바의 동시 노출 여부를 고려해 높이를 계산한다.

### 5.3 키보드 대응

- 입력 필드 포커스 시 화면이 적절히 이동해야 한다.
- 키보드가 열린 동안 하단 탭바는 숨긴다.
- 입력창은 키보드 위에서 접근 가능해야 한다.
- iOS Safari의 viewport 변화에 대응한다.
- 키보드가 닫힌 후 스크롤 위치가 비정상적으로 이동하지 않아야 한다.

### 5.4 스크롤

- 헤더와 하단 CTA는 고정
- 본문만 스크롤
- 중첩 스크롤 최소화
- 바텀시트 내부 스크롤과 배경 스크롤 분리
- 마지막 항목이 CTA에 가려지지 않아야 한다.

### 5.5 접근성

- 모든 버튼 터치 영역 최소 44×44px
- 텍스트 대비 WCAG AA 기준 검증
- 상태는 색상 외 텍스트로도 전달
- 라디오·체크박스·토글에 접근 가능한 이름 제공
- 선택 상태를 스크린리더에 전달
- 글자 크기 확대에 대응
- 모션 감소 설정 존중
- 오류 발생 시 해당 필드와 오류 문구 연결

## 6. 개발 우선순위

### P0 — 반드시 먼저 수정

1. 재조율 후보의 조건 충족 상태와 실제 충돌 데이터 일치
2. 회의 생성부터 상세까지 데이터 정합성 확인
3. 고정 CTA와 스크롤 콘텐츠 겹침 해결
4. 참석 가능 응답과 캘린더 상태 구분
5. 확정 후 NODI 저장과 외부 처리 결과 구분
6. 변경된 후보의 기존 응답 유효성 판단
7. 모바일 키보드와 safe area 대응

### P1 — 시각적 완성도 개선

1. 공통 타이포그래피 적용
2. 카드 내부 패딩과 간격 통일
3. 상태 배지 스타일 표준화
4. 추천 카드 정보 위계 개선
5. 참석자 선택 화면 밀도 축소
6. 재조율 모달 간소화
7. 받은 요청과 내 회의 목록 개선
8. 반복 설명 축약

### P2 — 사용성 고도화

1. 추천 근거 펼치기
2. 참석자 선택 요약 접기
3. 필터 및 검색 편의성 개선
4. 긴 목록의 빈 상태·로딩 상태 개선
5. 애니메이션 및 전환 효과 정교화

## 7. QA 체크리스트

### 공통 UI

- [ ] 16개 화면의 제목 크기가 일관적인가?
- [ ] 주요 CTA 높이가 통일되어 있는가?
- [ ] 카드 패딩과 radius가 일관적인가?
- [ ] 상태 배지의 색상과 의미가 일치하는가?
- [ ] 긴 텍스트가 잘리거나 겹치지 않는가?
- [ ] 화면 하단 콘텐츠가 CTA에 가려지지 않는가?

### 데이터 및 상태

- [ ] 회의 제목, 날짜, 시간, 참석 인원이 화면 간 일치하는가?
- [ ] 필수 참석자 충돌이 있을 때 조건 충족으로 표시되지 않는가?
- [ ] 참석 가능 응답과 캘린더 조회 결과가 구분되는가?
- [ ] 응답 대기와 참석 불가를 구분하는가?
- [ ] NODI 저장과 외부 캘린더 반영을 구분하는가?
- [ ] 데모 알림을 실제 발송으로 표현하지 않는가?

### 인터랙션

- [ ] 바텀시트가 열리고 닫히는가?
- [ ] 닫을 때 변경사항 유실을 방지하는가?
- [ ] 버튼 중복 클릭을 방지하는가?
- [ ] 비활성 버튼의 사유를 알 수 있는가?
- [ ] 선택 상태가 명확한가?
- [ ] 뒤로 가기 후 입력값이 유지되는가?
- [ ] 키보드가 열려도 입력과 제출이 가능한가?

### 재조율

- [ ] 새 시간이 확정되기 전 기존 회의가 유지되는가?
- [ ] 변경 전후 일정이 정확히 비교되는가?
- [ ] 기존 응답을 재사용할 수 있는 조건이 명확한가?
- [ ] 새 응답이 필요한 참석자와 후보가 정확히 표시되는가?
- [ ] 변경 확정 이후 회의 상세에 최신 일정이 반영되는가?

## 8. Claude 개발 전달 지시문

아래 지시문을 현재 NODI 프로젝트와 함께 전달한다.

> 첨부한 NODI 모바일 시안 16개와 이 UX/UI 개선 명세서를 기준으로 기존 UI를 개선해 주세요.
>
> 기존 NODI 브랜드, 로고, 주요 컬러, 3개 하단 탭, 핵심 사용자 흐름은 유지합니다.
>
> 전체 디자인을 새로 만드는 것이 아니라 다음을 우선 수정합니다.
>
> 1. 타이포그래피, 간격, 카드, 버튼, 배지의 공통 디자인 토큰을 정리합니다.
> 2. 모든 화면에 동일한 컴포넌트 스타일을 적용합니다.
> 3. 추천 카드와 재조율 카드의 정보 위계를 개선합니다.
> 4. 추천 조건 충족 여부와 실제 참석자 충돌 데이터가 모순되지 않도록 검증합니다.
> 5. 하단 고정 CTA, 바텀시트, 키보드, safe area 문제를 해결합니다.
> 6. NODI 내부 확정, 외부 캘린더, 데모 알림 상태를 분리합니다.
> 7. 작은 모바일부터 큰 모바일까지 반응형으로 동작하도록 합니다.
>
> 작업 전 현재 구현을 분석하고, 실제로 존재하는 기능과 데모 기능을 구분해 주세요.
>
> 변경하지 않아도 되는 구조는 유지하고, 수정이 필요한 컴포넌트만 개선합니다.
>
> 구현 후에는 화면별 변경사항, 수정된 컴포넌트, 남은 이슈, 모바일 QA 결과를 정리해 주세요.
>
> UI에 표시되는 상태 문구는 실제 데이터와 반드시 일치해야 합니다.

## 9. 최종 완료 기준

이번 개선 작업은 단순히 화면이 예뻐지는 것으로 완료하지 않는다.

다음 조건을 모두 충족해야 한다.

1. **시각적 일관성:** 16개 화면에 동일한 디자인 시스템이 적용된다.
2. **정보 명확성:** 사용자가 현재 상태와 다음 행동을 이해할 수 있다.
3. **데이터 신뢰성:** 추천·확정·재조율 상태에 모순이 없다.
4. **모바일 조작성:** 작은 화면에서도 모든 정보와 버튼에 접근할 수 있다.
5. **실제 기능 일치:** 데모와 실제 처리를 명확히 구분한다.
6. **접근성:** 텍스트 대비, 터치 영역, 선택 상태, 키보드 조작을 검증한다.

**최종 방향:** NODI의 브랜드 정체성과 기존 사용자 흐름을 유지하면서, 정보 위계·상태 정확성·모바일 사용성을 중심으로 제품 완성도를 높인다.
