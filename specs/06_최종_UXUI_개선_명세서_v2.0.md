# NODI 최종 UX/UI 개선 명세서

**Version:** 2.0  
**대상:** NODI 모바일 우선 반응형 웹 및 앱  
**검토 기준:** 수정 시안 16개 화면  
**목표:** 제품 완성도 향상, 사용 흐름 단순화, 회의 상태에 대한 신뢰 확보

---

## 1. 최종 디자인 방향

### 핵심 콘셉트: Soft Clarity

NODI는 AI가 회의를 대신 판단하는 서비스가 아니라, **사용자가 복잡한 일정 조건을 빠르고 명확하게 판단하도록 돕는 AI 회의 조율 서비스**다.

디자인은 다음 세 가지 원칙을 따른다.

1. **Clear:** 사용자가 현재 단계와 다음 행동을 즉시 이해한다.
2. **Calm:** 불필요한 카드, 배지, 강조 색상을 줄여 시각적 피로를 낮춘다.
3. **Trustworthy:** AI 해석, 캘린더 정보, 참석자 응답, 최종 확정 상태를 정확하게 구분한다.

### 유지할 요소

- 기존 NODI 로고와 브랜드 아이덴티티
- Primary Blue `#3654D4`
- Navy `#18243A`
- Canvas `#F5F7FB`
- AI 기반 자연어 회의 생성
- 회의 조건 확인 및 수정
- 참석자 선택과 일정 필수 참석자 지정
- 조율 현황, 추천 시간, 최종 검토
- 내 회의, 받은 요청, 재조율 기능
- 모바일 하단 3탭 내비게이션

**전체 디자인을 새롭게 갈아엎지 않는다.** 기존 브랜드와 기능을 유지하면서 컴포넌트 크기, 정보 위계, 화면 밀도, 상태 표현을 개선한다.

## 2. 가장 중요한 개선 원칙

### 원칙 1. 한 화면에는 하나의 주요 행동만 둔다

각 화면에서 가장 중요한 CTA를 하나로 제한한다.

| 화면 | 주요 행동 |
|---|---|
| AI 조건 확인 | 조건 확인하고 다음 |
| 조건 수정 | 변경사항 저장 |
| 참석자 선택 | 참석자 선택 완료 |
| 일정 필수 설정 | 설정 완료 |
| 조율 현황 | 추천 시간 보기 |
| 추천 시간 | 선택한 시간 검토 |
| 최종 검토 | 회의 확정하기 |
| 완료 | 회의 상세 보기 |
| 재조율 후보 | 선택한 새 시간 검토 |
| 변경 내용 검토 | 새 일정 변경 진행 |
| 받은 요청 응답 | 응답 제출하기 |

보조 행동은 텍스트 버튼이나 아웃라인 버튼으로 표현한다.

### 원칙 2. 사용자의 결정에 필요한 정보부터 보여준다

모든 정보는 다음 순서로 배치한다.

1. 현재 상황 또는 결론
2. 사용자가 결정해야 할 사항
3. 결정에 필요한 핵심 근거
4. 추가 설명 및 상세 정보

긴 정책 설명, 예외 조건, 데이터 출처는 기본 화면에서 반복하지 않는다. 필요한 곳에서만 펼쳐 보도록 한다.

### 원칙 3. 상태와 선택을 시각적으로 구분한다

- 파란색: 사용자의 선택, 주요 CTA, 현재 단계
- 초록색: 검증된 조건 충족 또는 처리 성공
- 노란색: 응답 대기, 확인 필요
- 빨간색: 확인된 충돌, 오류, 처리 실패
- 회색: 미선택, 보조 정보, 아직 확인되지 않은 상태

초록색이라고 해서 사용자가 선택한 후보라는 의미가 되어서는 안 된다. 선택 여부는 파란 테두리와 라디오 버튼으로 표시한다.

## 3. 최종 권장 사용자 흐름

### A. 새 회의 생성

**자연어 입력 → 조건 확인 → 참석자 선택 → 일정 필수 설정 → 조율 현황 → 추천 시간 → 최종 검토 → NODI 회의 확정**

각 단계의 목적을 분명히 한다.

#### 1단계. 조건 확인

사용자가 입력한 자연어를 AI가 구조화한다.

사용자는 제목, 회의 길이, 날짜 범위, 선호 시간대, 참석 방식 등을 확인하고 수정할 수 있다.

AI가 추출한 조건은 확정된 사실이 아니라 **사용자 확인이 필요한 초안**이다.

#### 2단계. 참석자 선택 및 일정 필수 설정

참석자를 먼저 선택하고, 그중 누구의 일정 충돌을 우선적으로 피할지 지정한다.

`일정 필수`는 해당 참석자의 캘린더 조건을 우선 적용한다는 의미이며, **참석 수락을 의미하지 않는다.**

#### 3단계. 조율 현황

참석자의 응답 제출 상태와 캘린더 조회 상태를 보여준다.

응답 제출률과 참석 가능률을 혼동하지 않도록 한다.

#### 4단계. 추천 시간

NODI가 조건에 따라 후보 시간을 제안한다.

추천 이유는 실제 확인된 정보만 사용한다.

#### 5단계. 최종 검토

사용자가 시간, 참석자, 일정 필수 조건, 외부 처리 방식을 확인한다.

#### 6단계. 확정 및 완료

NODI 내부 회의 저장 결과와 외부 캘린더·알림 처리 상태를 각각 보여준다.

### B. 재조율

**회의 상세 → 재조율 시작 → 새 후보 선택 → 변경 내용 검토 → 변경 처리 결과**

재조율 과정에서는 기존 회의를 즉시 변경하지 않는다.

사용자가 최종 변경을 진행하기 전까지 기존 확정 일정은 유지한다.

새 후보에 대한 응답이 필요한 경우, 새 일정이 모든 참석자에게 확정된 것처럼 표현하지 않는다.

### C. 받은 요청

**받은 요청 → 후보별 응답 → 제출 완료**

변경된 요청이라면 이전 응답 중 유지되는 항목과 새로 응답해야 하는 항목을 구분한다.

## 4. GUI 디자인 시스템 개선

### 4.1 타이포그래피

| 요소 | 크기 | 굵기 |
|---|---|---|
| 화면 제목 | 24px | 700 |
| 핵심 시간 및 날짜 | 26~28px | 700 |
| 섹션 제목 | 18px | 650 |
| 카드 제목 | 16~18px | 600 |
| 기본 본문 | 15~16px | 400 |
| 보조 정보 | 13~14px | 400 |
| 배지 | 12~13px | 600 |
| 버튼 | 16px | 600 |

**적용 규칙**

- 한 화면에서 24px 이상 텍스트를 남용하지 않는다.
- 주요 시간과 날짜만 크게 강조한다.
- 모든 설명을 굵은 글씨로 표현하지 않는다.
- 부가 정보는 짧은 문장으로 정리한다.
- 본문 줄 간격은 약 1.45~1.6배를 사용한다.

### 4.2 컬러

| 역할 | 색상 |
|---|---|
| Primary | `#3654D4` |
| Text Primary | `#18243A` |
| Background | `#F5F7FB` |
| Surface | `#FFFFFF` |
| Text Secondary | `#64748B` |
| Border | `#E2E8F0` |
| Success | `#13845F` |
| Warning | `#A16207` |
| Error | `#C93646` |

성공, 경고, 오류 색상은 의미 전달을 위해 사용한다. 브랜드 블루를 상태 색상처럼 남용하지 않는다.

색상은 접근성 대비 기준을 확인하고 최종 확정한다.

### 4.3 간격

4px 기반 간격 체계를 사용한다.

- 화면 좌우 여백: 20px
- 섹션 간격: 24~32px
- 카드 간격: 12~16px
- 카드 내부 여백: 16~20px
- 제목과 설명 간격: 6~8px
- 관련 정보 간격: 8~12px

현재 시안처럼 모든 카드에 큰 패딩을 적용하지 않는다.

### 4.4 모서리와 테두리

- 기본 카드: 16px
- 바텀시트 상단: 24px
- 입력 필드: 12px
- 주요 버튼: 14px
- 배지: Pill
- 기본 테두리: 1px

모든 컴포넌트를 과도하게 둥글게 만들지 않는다.

### 4.5 버튼

- 주요 버튼 높이: 52~56px
- 보조 버튼 높이: 44~48px
- 아이콘 터치 영역: 최소 44×44px
- 주요 CTA는 화면 하단 고정 가능
- 하단 CTA 영역은 safe area를 고려한다.

비활성 버튼은 비활성 이유를 화면에서 알 수 있어야 한다.

예: `후보를 선택해 주세요`

## 5. 화면별 최종 개선안

### 01. AI 조건 확인

**문제**

- 채팅 말풍선과 조건 카드가 모두 커서 화면이 길다.
- 조건 확인 카드가 입력창과 하단 내비게이션에 가려진다.
- 다음 단계로 진행하는 행동이 명확하지 않다.

**개선**

1. AI 대화는 상단에 간결하게 유지한다.
2. 사용자의 입력은 한 개의 메시지로 보여준다.
3. AI의 안내 문장은 짧게 줄인다.
4. 조건 확인 카드는 화면의 중심 콘텐츠로 배치한다.
5. 조건 카드는 제목, 길이, 날짜, 시간대, 참석 방식을 행 단위로 요약한다.
6. 각 조건은 편집 버튼 또는 전체 수정 버튼으로 수정할 수 있다.
7. 하단 주요 CTA를 `조건 확인하고 참석자 선택`으로 설정한다.
8. 조건 확인 중에는 채팅 입력창과 하단 탭바가 CTA를 가리지 않도록 한다.

**권장 문구**

- 제목: `회의 조건을 확인해 주세요`
- 설명: `말씀하신 내용을 이렇게 이해했어요. 필요한 부분은 수정할 수 있어요.`
- CTA: `조건 확인하고 참석자 선택`

### 02. 회의 조건 수정

**문제**

- 회의 길이 버튼 5개가 한 줄에 배치되어 답답하다.
- 날짜 선택과 기간 선택의 차이가 직관적이지 않다.
- 바텀시트의 콘텐츠와 하단 버튼이 지나치게 크다.

**개선**

1. 바텀시트는 화면 높이에 맞춰 스크롤한다.
2. 회의 길이는 대표 옵션과 직접 설정으로 구성한다.
3. 날짜 모드를 `하루 선택`과 `기간 선택`으로 표현한다.
4. 하루 선택 시 특정 날짜 하나만 선택한다.
5. 기간 선택 시 시작일과 종료일을 명확히 보여준다.
6. 날짜 선택 결과를 한 줄 요약으로 보여준다.
7. 선호 시간대는 오전, 오후, 상관없음으로 구성한다.
8. 참석 방식은 온라인, 오프라인, 미정 등 실제 지원하는 옵션만 보여준다.
9. 변경사항이 있을 때만 저장 CTA를 활성화한다.

**권장 문구**

- `특정 날짜` → `하루 선택`
- `기간` → `기간 선택`
- `변경된 내용이 없어요` → 버튼 비활성 상태의 보조 설명

### 03. 참석자 선택

**문제**

- 선택된 사람의 칩이 커서 목록을 밀어낸다.
- 선택된 참석자와 검색 결과가 동시에 복잡하게 보인다.
- 동명이인 정보가 과도하게 강조된다.

**개선**

1. 상단에 검색창을 고정한다.
2. 팀 필터는 가로 스크롤 가능한 작은 칩으로 구성한다.
3. 선택된 참석자는 `선택한 참석자 3명` 요약 영역으로 표시한다.
4. 선택 인원이 많아지면 칩 영역을 접을 수 있게 한다.
5. 참석자 행은 이름, 팀, 필요한 식별 정보만 표시한다.
6. 동명이인은 동일 이름이 실제로 중복될 때 팀과 이메일을 강조한다.
7. 하단 CTA에 선택 인원을 표시한다.

**권장 CTA**

`3명 선택하고 다음`

### 04. 일정 필수 설정

**문제**

- 정책 선택 카드가 너무 커서 참석자 설정이 아래로 밀린다.
- 일정 필수의 의미가 길게 설명된다.
- 정책과 개인별 스위치의 관계가 즉시 이해되지 않는다.

**개선**

1. 정책 선택을 간결한 라디오 리스트로 표현한다.
2. 기본 정책은 `일정 필수 참석자 우선`으로 설정한다.
3. 선택한 정책의 설명만 노출한다.
4. 참석자별 일정 필수 여부는 리스트와 스위치로 설정한다.
5. `일정 필수는 참석 수락을 의미하지 않아요`를 한 번만 표시한다.
6. `전원 일정 조건 충족`을 선택하면 개인별 스위치의 역할을 명확히 처리한다.

**권장 문구**

- `일정 필수 참석자 우선`
- `모든 참석자의 일정 조건 충족`
- `일정 필수 1명 설정 완료`

### 05. 조율 진행 현황

**문제**

- 응답 제출, 조정하면 가능, 재확인 필요가 한 카드에 혼합되어 있다.
- 숫자가 무엇을 기준으로 계산됐는지 이해하기 어렵다.
- 리마인드 버튼이 실제 알림 발송처럼 보일 수 있다.

**개선**

1. 상단에 응답 제출 현황만 요약한다.
2. `2/3명 응답 제출`을 가장 크게 표시한다.
3. 제출 완료, 응답 대기, 재확인 필요를 구분한다.
4. 참석자별 상태는 아래 목록에서 보여준다.
5. 캘린더 조회 여부와 참석자 응답 여부를 별도 상태로 표시한다.
6. `조정하면 가능`은 해당 응답의 의미를 설명하거나 후보별 상세에서 보여준다.
7. 리마인드가 데모 처리라면 실제 발송이 아니라는 점을 명확히 표시한다.

**권장 구조**

- 응답 제출: 2/3명
- 응답 완료: 2명
- 응답 대기: 1명
- 참석자별 상태
- CTA: `추천 시간 보기`

### 06. 추천 회의 시간

**최우선 GUI 개선 화면**

**문제**

- 추천 카드가 지나치게 길다.
- 숫자와 상태 정보가 동등한 중요도로 표시된다.
- 캘린더상 충돌 없음과 참석 가능 응답이 혼동될 수 있다.
- 사용자가 어떤 후보를 선택해야 하는지 한눈에 판단하기 어렵다.

**개선**

1. 상단 조건 요약은 한 개의 컴팩트한 카드로 표현한다.
2. 추천 후보는 시간 중심의 카드로 구성한다.
3. 카드에서 가장 크게 보여줄 정보는 날짜와 시간이다.
4. `NODI 추천`은 첫 번째 추천 후보에만 표시한다.
5. `필수 조건 충족`은 작은 상태 배지로 표시한다.
6. 참석 가능 응답과 캘린더상 충돌 없음을 구분한다.
7. 추천 근거는 기본 1~2줄만 표시한다.
8. 상세 근거는 펼쳐 보기로 제공한다.
9. 후보 선택은 라디오 버튼과 선택 테두리로 표시한다.
10. 선택된 후보가 있을 때 CTA를 활성화한다.
11. 후보 비교는 보조 기능으로 유지한다.

**권장 카드 구성**

- NODI 추천
- 11월 24일 화요일
- **오후 2:00–3:00**
- 필수 일정 조건 충족
- 가능 응답 2명 · 캘린더상 충돌 없음 1명
- 추천 근거 자세히 보기

**주의**

캘린더상 충돌이 없다는 사실만으로 참석자가 참석을 수락했다고 표현하지 않는다.

### 07. 최종 검토

**문제**

- 회의 요약과 확정 후 처리 설명이 길다.
- 사용자가 확정 버튼을 누르면 정확히 무엇이 완료되는지 불명확하다.

**개선**

1. 상단에 최종 회의 요약을 배치한다.
2. 제목, 날짜, 시간, 참석자, 일정 필수 참석자를 간결하게 보여준다.
3. 응답과 캘린더 상태를 별도 섹션으로 보여준다.
4. 외부 처리 옵션은 `확정 후 처리` 영역으로 구분한다.
5. 실제로 지원하지 않는 캘린더 반영이나 알림 발송을 약속하지 않는다.
6. CTA 주변에 처리 범위를 짧게 설명한다.

**권장 문구**

- 제목: `이 일정으로 회의를 확정할까요?`
- 설명: `확정하면 NODI에 회의가 저장돼요.`
- CTA: `회의 확정하기`

### 08. 확정 완료

**문제**

- 회의 확정 성공보다 외부 작업 경고가 더 강하게 보인다.
- 데모 알림의 처리 실패가 실제 발송 실패처럼 읽힐 수 있다.

**개선**

1. 상단은 회의 저장 성공을 중심으로 구성한다.
2. 회의 제목과 확정 시간을 보여준다.
3. `외부 처리 현황`은 하단 보조 섹션으로 분리한다.
4. 캘린더 미연결 상태를 명확히 표시한다.
5. 데모 알림은 실제 전송과 구분한다.
6. 실패한 작업만 재시도 버튼을 제공한다.
7. 기본 CTA는 `회의 상세 보기`로 설정한다.

**권장 문구**

`NODI에 회의가 저장됐어요`

보조 설명:

`캘린더 연결과 알림 처리는 별도로 확인할 수 있어요.`

### 09. 내 회의

**문제**

- 회의 목록의 정보 밀도가 낮다.
- 회의별 상태 배지가 상대적으로 크다.
- 회의 상태와 후속 조치가 같은 위계로 표현된다.

**개선**

1. 날짜를 왼쪽, 회의 정보를 오른쪽에 배치한다.
2. 제목을 가장 먼저 보여준다.
3. 시간과 참석자 수는 한 줄로 정리한다.
4. 상태 배지는 작게 유지한다.
5. 확인이 필요한 항목은 보조 문구로 표시한다.
6. 회의 행 전체를 눌러 상세로 이동할 수 있게 한다.

### 10. 회의 상세

**문제**

- 캘린더와 알림 처리 상태가 화면을 과도하게 차지한다.
- 실제 회의 정보보다 시스템 상태가 더 중요해 보인다.

**개선**

1. 회의 제목과 날짜, 시간을 가장 먼저 보여준다.
2. NODI 저장 상태를 간단한 배지로 표시한다.
3. 참석자 정보와 회의 조건을 주요 콘텐츠로 배치한다.
4. 캘린더와 알림은 `외부 처리 상태` 섹션으로 묶는다.
5. 정상 상태는 한 줄로 표시한다.
6. 오류가 있을 때만 상세 메시지와 재시도 버튼을 펼쳐 보여준다.
7. 재조율과 회의 수정은 별도 행동으로 구분한다.

### 11. 재조율 시작 확인

**문제**

- 모달의 문장과 높이가 길다.
- 기존 회의 유지 규칙을 이해하기 위해 많은 내용을 읽어야 한다.

**개선**

1. 모달 제목을 짧게 만든다.
2. 핵심 규칙을 두 문장 이내로 설명한다.
3. 기본 CTA와 취소 행동을 명확히 구분한다.

**권장 문구**

제목: `새 시간을 찾아볼까요?`

설명: `새 일정으로 변경하기 전까지 기존 회의는 유지돼요.`

CTA: `새 시간 찾기`

보조 버튼: `취소`

### 12. 재조율 후보

**심각한 상태 검증 필요**

**문제**

- `필수 조건 충족`과 `필수 참석자 캘린더 충돌`이 같은 후보에 표시된다.
- 기존 응답과 새 응답이 혼합되어 보인다.
- 후보별 위험 상태를 빠르게 이해하기 어렵다.

**개선**

1. 추천 후보를 표시하기 전에 필수 조건을 검증한다.
2. 필수 참석자 충돌이 확인되면 `필수 조건 미충족`으로 처리한다.
3. 미충족 후보는 기본 추천에서 제외한다.
4. 기존 응답이 유지되는 항목과 새 응답이 필요한 항목을 구분한다.
5. 후보 카드에서 충돌, 응답 대기, 재확인 필요를 별도로 표시한다.
6. 기존 확정 일정은 화면 상단에 작게 유지 상태로 표시한다.

**필수 로직**

동일한 조건과 데이터 시점에서 필수 참석자의 확인된 충돌이 존재한다면 해당 후보를 `필수 조건 충족`으로 표시하지 않는다.

### 13. 변경 내용 검토

**문제**

- 변경 확정과 참석자 재확인 요청이 하나의 행동처럼 표현된다.
- 변경 이후 회의 상태가 무엇인지 불분명하다.

**개선**

1. 기존 일정과 새 일정을 위아래로 비교한다.
2. 변경된 항목만 강조한다.
3. 재응답이 필요한 인원을 표시한다.
4. 변경 후 기존 회의가 어떻게 처리되는지 설명한다.
5. 실제 상태 전환 정책과 CTA 문구를 일치시킨다.

**권장 문구**

재응답이 필요한 정책이라면:

`새 일정으로 변경하고 재확인 요청`

단, 실제 알림이 데모 처리라면 `요청 발송`을 완료했다고 표현하지 않는다.

### 14. 받은 요청

**문제**

- 카드가 크고 정보량은 적다.
- 응답 필요와 재확인 필요의 차이가 충분히 드러나지 않는다.

**개선**

1. 요청을 컴팩트한 카드 또는 리스트로 표현한다.
2. 제목, 요청자, 마감일을 우선 표시한다.
3. `응답 필요`와 `재확인 필요`를 명확히 구분한다.
4. 카드의 CTA를 구체적으로 표시한다.

**권장 CTA**

- 일반 요청: `가능 시간 응답하기`
- 변경 요청: `변경된 후보 확인하기`

### 15. 참석 가능 시간 응답

**문제**

- 후보별 카드와 선택 버튼이 지나치게 크다.
- 후보가 여러 개일 때 스크롤 부담이 크다.
- 저장과 제출의 차이가 충분히 강조되지 않는다.

**개선**

1. 각 후보를 컴팩트한 카드로 구성한다.
2. 날짜와 시간을 상단에 표시한다.
3. 응답 옵션은 `가능 / 조정 가능 / 불가`로 통일한다.
4. 선택 상태는 블루 배경과 체크 표시로 보여준다.
5. 모든 후보에 응답해야 제출 가능하도록 한다.
6. 임시 저장 상태를 제출 상태와 구분한다.
7. CTA는 `응답 제출하기`로 표현한다.

### 16. 조건 변경된 요청

**문제**

- 변경 안내 카드가 너무 크다.
- 이전 응답과 새 응답의 차이가 한눈에 보이지 않는다.

**개선**

1. 상단에 `회의 시간이 변경됐어요`를 간결하게 표시한다.
2. 변경된 후보만 우선 보여준다.
3. 유지되는 응답은 접힌 섹션으로 처리한다.
4. 새 응답이 필요한 후보 수를 표시한다.
5. 변경된 후보에 대한 응답을 완료하면 제출 CTA를 활성화한다.

**권장 CTA**

`변경된 후보 응답 제출`

## 6. 상태 정의 및 데이터 정합성

UI보다 먼저 아래 상태 정의를 일관되게 적용한다.

### 참석자 응답 상태

- 응답 대기
- 가능
- 조정하면 가능
- 불가
- 재확인 필요

### 캘린더 상태

- 조회 전
- 조회 불가
- 충돌 없음
- 충돌 있음

### 회의 상태

- 조건 작성 중
- 참석자 조율 중
- 추천 시간 검토 중
- NODI 확정
- 재조율 중
- 취소됨

### 외부 처리 상태

- 처리 전
- 처리 중
- 완료
- 일부 실패
- 연결 안 됨
- 데모 처리

### 필수 검증 규칙

1. 응답 대기는 참석 가능으로 계산하지 않는다.
2. 캘린더 충돌 없음은 참석 수락으로 계산하지 않는다.
3. 필수 참석자의 확인된 충돌이 있으면 필수 조건 충족으로 표시하지 않는다.
4. 후보 시간이 변경되면 해당 시간에 대한 응답의 유효성을 다시 판단한다.
5. 재조율 시 기존 응답을 무조건 새 후보에 재사용하지 않는다.
6. NODI 내부 저장과 외부 캘린더 반영을 구분한다.
7. 데모 알림과 실제 발송을 구분한다.
8. 상태를 표시하는 수치는 모두 동일한 데이터 버전과 기준 시점을 사용한다.

## 7. 모바일 UX 개선

### 하단 내비게이션

기존 3개 탭을 유지한다.

- 회의 잡기
- 내 회의
- 받은 요청

단, 회의 생성과 같은 집중형 작업에서는 하단 탭바를 숨길 수 있다.

### 키보드

- 입력창 포커스 시 키보드가 CTA를 가리지 않도록 한다.
- iOS Safari의 viewport 변화와 safe area를 고려한다.
- 키보드가 열리면 불필요한 하단 내비게이션을 숨긴다.

### 바텀시트

- 상단 핸들과 닫기 버튼을 제공한다.
- 내용 영역만 스크롤한다.
- 하단 CTA는 고정한다.
- 닫을 때 미저장 변경사항이 있으면 확인한다.
- 입력 필드에 포커스했을 때 해당 필드가 가려지지 않도록 한다.

### 접근성

- 터치 영역 최소 44×44px
- 본문과 배지의 명도 대비 확인
- 색상만으로 상태를 구분하지 않음
- 스크린리더에 선택 및 상태 정보 제공
- 시스템 글자 크기 확대 시 레이아웃 확인
- 비활성 버튼의 이유를 텍스트로 제공

- [ ] 필수 참석자 충돌 후보가 정상 추천으로 표시되지 않는다.
- [ ] 새 응답이 필요한 사람을 알 수 있다.
- [ ] 변경 CTA의 문구가 실제 처리와 일치한다.

### 받은 요청

- [ ] 일반 요청과 재확인 요청이 구분된다.
- [ ] 후보별 응답을 쉽게 선택할 수 있다.
- [ ] 임시 저장과 제출 완료가 구분된다.
- [ ] 변경된 후보만 다시 응답할 수 있다.

### 모바일

- [ ] 하단 CTA가 시스템 홈 인디케이터와 겹치지 않는다.
- [ ] 키보드가 입력창을 가리지 않는다.
- [ ] 바텀시트 내부 스크롤이 정상 동작한다.
- [ ] 긴 콘텐츠가 잘리지 않는다.
- [ ] 작은 화면과 큰 글자 설정에서도 조작 가능하다.

## 10. Claude 개발 및 디자인 수정 지시

기존 NODI 구현을 기반으로 다음 작업을 진행한다.

### 작업 지침

1. 기존 NODI 로고, 브랜드 색상, 주요 기능을 유지한다.
2. 16개 화면의 전체 UI를 디자인 시스템 기준으로 정리한다.
3. 모든 화면을 새로 만드는 대신 공통 컴포넌트를 개선한다.
4. 먼저 상태 정의와 추천 검증 로직을 수정한다.
5. 추천 시간 화면을 가장 높은 GUI 완성도로 재설계한다.
6. 이후 조건 수정, 참석 가능 시간 응답, 회의 상세 화면을 개선한다.
7. 모든 카드, 버튼, 배지, 입력 필드, 바텀시트에 동일한 규칙을 적용한다.
8. 불필요한 카드 중첩과 반복 설명을 제거한다.
9. 주요 CTA는 한 화면에 하나만 두고 보조 행동과 구분한다.
10. iOS 및 Android 모바일 환경에서 실제 화면 크기와 키보드 동작을 확인한다.

### 반드시 지킬 사항

- AI가 실제로 확인하지 않은 사실을 확정적으로 표현하지 않는다.
- 참석자 응답과 캘린더 상태를 혼동하지 않는다.
- NODI 저장을 외부 캘린더 반영이나 초대 발송으로 표현하지 않는다.
- 재조율 중 기존 회의의 유지 여부를 명확히 한다.
- 필수 조건 미충족 후보를 정상 추천처럼 표시하지 않는다.
- 데모 기능을 실제 외부 연동처럼 표현하지 않는다.

### 요청 결과물

1. 개선된 16개 화면
2. 공통 디자인 토큰
3. 버튼, 카드, 배지, 입력 필드, 바텀시트 컴포넌트
4. 화면별 상태 및 인터랙션 정의
5. 추천 후보 검증 로직 수정 내역
6. 모바일 반응형 QA 결과
7. 기존 화면 대비 변경 사항 요약

## 11. 완료 기준

이번 개선은 단순히 화면이 예뻐지는 것으로 끝나지 않는다.

다음 조건을 충족해야 한다.

- 사용자가 각 화면에서 다음 행동을 바로 찾을 수 있다.
- 중요한 정보가 첫 화면에 보인다.
- 같은 상태가 모든 화면에서 같은 용어와 색상으로 표현된다.
- 추천 이유를 실제 데이터로 설명할 수 있다.
- 회의 확정과 외부 처리의 차이를 이해할 수 있다.
- 재조율 시 기존 회의와 새 일정의 관계가 명확하다.
- 화면의 카드, 여백, 글자, 버튼이 일관된 디자인 시스템을 따른다.
- 모바일에서 스크롤, 키보드, 바텀시트, CTA가 안정적으로 작동한다.

**최종 목표는 '기능이 많아 보이는 서비스'가 아니라 '복잡한 회의 조율을 쉽게 결정할 수 있는 서비스'를 만드는 것이다.**
