# NODI 최종 UX/UI 개선 및 구현 프롬프트 v2.0

> **목적:** 기존 NODI 서비스의 브랜드와 핵심 기능을 유지하면서, 모바일 중심의 사용 흐름과 시각적 완성도를 개선한다.  
> **대상:** Claude 개발 및 디자인 구현  
> **우선 환경:** iOS 스타일 모바일 웹, 반응형 웹, 설치형 모바일 앱  
> **핵심 방향:** 선택형 + 자유 입력 하이브리드, Soft Clarity, 명확한 상태 표현, 여유 있는 모바일 레이아웃

---

## 0. Claude에게 전달하는 최상위 지시사항

당신은 시니어 프로덕트 디자이너이자 프런트엔드 엔지니어입니다.

현재 구현된 NODI의 기능과 디자인을 기반으로 UX/UI를 개선하세요. 새로운 서비스를 처음부터 디자인하는 작업이 아닙니다.

### 반드시 지킬 원칙

1. 기존 NODI 로고, 브랜드 컬러, 핵심 기능, 데이터 흐름을 유지합니다.
2. 기존 화면을 단순히 더 화려하게 만드는 것이 아니라, 사용자의 이해와 조작 편의성을 높입니다.
3. 모바일에서 한 화면에 너무 많은 정보를 배치하지 않습니다.
4. 화면마다 다른 컴포넌트 규칙을 만들지 않고 공통 디자인 시스템을 사용합니다.
5. 장식적인 아이콘, 중복된 배지, 불필요한 설명을 줄입니다.
6. 참석자의 **일정 가능 여부**, **참석 수락 여부**, **캘린더 상태**, **알림 처리 상태**를 서로 다른 개념으로 표현합니다.
7. AI가 추출한 조건은 사용자가 검토할 수 있어야 하며, 최종 확정은 명시적인 사용자 행동으로만 수행합니다.
8. 실제로 구현되지 않은 외부 캘린더 연동이나 알림 발송을 성공했다고 표시하지 않습니다.
9. 데모 데이터는 데모임을 명시합니다.
10. 기존 기능이 작동하는 상태를 유지하면서 화면별로 점진적으로 개선합니다.

### 최종 목표

사용자가 다음 흐름을 자연스럽게 완료할 수 있어야 합니다.

**회의 생성 시작 → 회의 조건 확인 → 참석자 선택 → 일정 필수 설정 → 일정 조율 → 추천 시간 확인 → 최종 검토 → 회의 저장 → 후속 처리 상태 확인**

# 1. 브랜드 및 디자인 방향

## 1.1 브랜드 유지

- 서비스명: NODI
- 브랜드 메시지: Better timing, together.
- 디자인 콘셉트: Soft Clarity
- 기존 NODI 로고 유지
- 기존 블루·퍼플 아이덴티티 유지
- 차분하고 신뢰감 있는 생산성 서비스 지향

### 주요 컬러

| 토큰 | 값 | 용도 |
|---|---|---|
| Primary | `#3654D4` | 주요 CTA, 선택 상태, 핵심 인터랙션 |
| Navy | `#18243A` | 제목, 주요 텍스트 |
| Canvas | `#F5F7FB` | 화면 배경 |
| Surface | `#FFFFFF` | 카드, 시트 |
| Purple Accent | 기존 브랜드 퍼플 | 로고 및 제한적 브랜드 강조 |

기존 코드의 컬러 토큰이 있다면 우선 재사용합니다.

### 상태 색상

- 성공: 차분한 그린
- 주의: 낮은 채도의 앰버
- 오류: 절제된 레드
- 중립·미연결·대기: 그레이
- 선택·진행: Primary Blue

**한 카드 안에서 수치마다 서로 다른 강조색을 반복하지 않습니다.**

# 2. 모바일 GUI 공통 규칙

## 2.1 여백 시스템

모바일에서 화면이 꽉 차 보이지 않도록 아래 규칙을 적용합니다.

| 요소 | 권장 기준 |
|---|---|
| 화면 좌우 여백 | 20px |
| 화면 상단 콘텐츠 여백 | 20~24px |
| 카드 내부 패딩 | 20px |
| 카드 사이 간격 | 12~16px |
| 섹션 사이 간격 | 28~32px |
| 관련 정보 사이 간격 | 8~12px |
| 버튼 최소 높이 | 48px |
| 터치 영역 최소 크기 | 44×44px |
| 카드 모서리 | 16~20px |
| 바텀시트 상단 모서리 | 24px |

좁은 화면에서는 16px 좌우 여백을 허용하지만, 화면마다 임의로 변경하지 않습니다.

## 2.2 타이포그래피

- 페이지 제목: 24px / Semibold
- 섹션 제목: 18~20px / Semibold
- 카드 핵심 정보: 18~22px / Semibold
- 일반 본문: 15~16px / Regular
- 보조 설명: 13~14px / Regular
- 배지: 12~13px / Medium

본문에 과도한 굵기를 사용하지 않습니다.

날짜와 시간은 중요도에 따라 크기를 구분하되, 같은 유형의 정보에는 동일한 스타일을 사용합니다.

## 2.3 시각적 위계

모든 화면에서 다음 순서를 우선합니다.

1. 현재 화면의 목적
2. 사용자가 확인해야 할 핵심 정보
3. 선택하거나 수정할 수 있는 요소
4. 보조 설명 및 근거
5. 주요 행동 버튼

하나의 카드에 제목, 배지, 아이콘, 설명, 수치, 경고를 모두 강조하지 않습니다.

## 2.4 카드 디자인

- 기본 카드 배경은 흰색
- 얇은 중립 테두리 사용
- 그림자는 필요할 때만 아주 약하게 적용
- 카드 안에 또 다른 카드를 반복해서 중첩하지 않음
- 관련성이 높은 정보만 하나의 카드에 묶음
- 긴 설명은 접기/펼치기 또는 상세 화면으로 이동

## 2.5 아이콘 사용 원칙

아이콘은 다음 목적일 때만 사용합니다.

- 뒤로 가기
- 닫기
- 검색
- 날짜 선택
- 정보 안내
- 중요한 성공 상태
- 중요한 오류 또는 경고

다음 경우에는 아이콘을 제거합니다.

- 텍스트만으로 충분히 이해되는 설정 목록
- 반복되는 참석자 상태
- 완료 처리 현황의 각 행
- 의미가 중복되는 카드 제목
- 이미 상태 배지가 있는 항목

**아이콘을 제거한 자리는 텍스트 정렬과 여백으로 정돈합니다.**

# 3. 회의 생성 시작 화면: 하이브리드 방식으로 변경

## 3.1 기존 문제

현재 자유 입력 중심의 시작 화면은 사용자가 처음부터 자연어로 회의 조건을 작성해야 합니다.

이 방식은 유연하지만 처음 사용하는 사용자에게 다음과 같은 부담을 줍니다.

- 무엇부터 입력해야 할지 모름
- 어떤 표현을 사용할 수 있는지 모름
- 회의 생성에 필요한 조건을 예측하기 어려움
- 입력창이 중심이어서 챗봇의 안내 역할이 약함

## 3.2 최종 방향

**선택형 + 자유 입력 하이브리드 챗봇**

챗봇이 회의 생성을 먼저 안내하고, 사용자는 추천 선택지를 누르거나 자유롭게 입력할 수 있어야 합니다.

선택형 UI가 자유 입력을 대체해서는 안 됩니다.

## 3.3 첫 화면 구성

### 상단

- NODI 로고
- 화면 제목: `회의 잡기`
- `새로 시작` 액션
- 불필요한 장식 제거

### 챗봇 첫 메시지

**추천 문구**

> 안녕하세요! 어떤 회의를 잡아드릴까요?  
> 아래에서 선택하거나 편하게 말씀해 주세요.

### 선택형 제안

기본적으로 3개의 주요 선택지를 노출합니다.

1. `팀 회의`
2. `1:1 미팅`
3. `디자인 리뷰`

추가 선택지:

- `다른 회의 직접 입력`

선택지는 모바일에서 가로 스크롤되는 작은 칩보다, 충분한 터치 영역을 가진 간결한 선택 카드 또는 2열 버튼 형태를 우선 검토합니다.

단, 화면이 복잡해지지 않도록 첫 화면에 4개 이상의 큰 카드를 동시에 쌓지 않습니다.

## 3.4 선택 후 챗봇 흐름

예시:

**NODI**

> 어떤 회의를 잡으시나요?

**사용자**

> 디자인 리뷰

**NODI**

> 좋아요. 언제쯤 진행하면 좋을까요?

선택지:

- `이번 주`
- `다음 주`
- `날짜 직접 선택`
- `직접 입력`

**NODI**

> 회의는 얼마나 진행할까요?

선택지:

- `30분`
- `60분`
- `90분`
- `직접 입력`

이후 참석자 선택 단계로 연결합니다.

### 중요한 UX 규칙

- 이미 사용자가 입력한 조건을 다시 묻지 않습니다.
- 자연어로 여러 조건을 입력했다면 한 번에 구조화합니다.
- 부족한 정보만 추가로 질문합니다.
- 선택한 항목은 대화에 반영하되, 모든 선택을 긴 채팅 말풍선으로 반복하지 않습니다.
- 질문은 가능한 한 한 번에 하나의 핵심 주제만 다룹니다.
- 뒤로 가기와 수정이 가능해야 합니다.

## 3.5 자유 입력 예시

사용자 입력:

> 다음 주 화요일 오후에 디자인팀 3명이랑 1시간 리뷰 미팅 잡아줘.

AI는 다음 항목을 추출합니다.

- 회의 제목: 디자인 리뷰
- 날짜: 다음 주 화요일
- 선호 시간: 오후
- 회의 길이: 60분
- 참석자: 디자인팀 3명 — 구체적인 인물 확인 필요

**팀 이름과 인원만으로 특정 참석자를 임의 확정하지 않습니다.**

AI 추출 후 바로 회의를 생성하지 말고 조건 확인 카드로 이동합니다.

# 4. 회의 조건 확인 화면

## 4.1 목적

AI가 이해한 조건을 사용자가 빠르게 검토하고 수정하는 화면입니다.

## 4.2 추천 구조

**제목**

> 회의 조건을 확인해 주세요

**보조 설명**

> 말씀하신 내용을 정리했어요. 필요한 항목만 수정할 수 있어요.

### 조건 요약 카드

- 회의 제목
- 회의 길이
- 날짜 또는 날짜 범위
- 선호 시간대
- 참석 방식

각 항목은 동일한 행 높이와 정렬 규칙을 사용합니다.

### 권장 행 구조

`항목명 | 현재 값 | 수정`

수정 아이콘을 모든 행에 반복하기보다, 행 전체를 누르면 수정할 수 있도록 하고 필요한 경우 우측에 작은 Chevron을 사용합니다.

## 4.3 날짜 UX

- `특정 날짜`와 `기간`을 명확히 구분
- 특정 날짜 선택 시 선택한 하루만 표시
- 기간 선택 시 시작일과 종료일 표시
- `다음 주` 같은 상대 날짜는 실제 날짜 범위로 변환해 확인
- 연도·월·일·요일 표기 일관성 유지

## 4.4 주요 CTA

`참석자 선택하기`

모든 필수 조건이 유효할 때 활성화합니다.

# 5. 참석자 선택 및 일정 필수 설정

## 5.1 참석자 선택

### 화면 구성

- 제목: `참석자 선택`
- 선택 인원 수
- 검색 입력
- 팀 필터
- 선택한 참석자 칩
- 참석자 목록
- 하단 고정 CTA

### 정렬 규칙

참석자 행은 공통 레이아웃을 사용합니다.

`선택 체크 | 아바타 | 이름 및 소속`

- 체크 영역 고정
- 아바타 크기 고정
- 이름 시작 위치 고정
- 소속은 이름 아래
- 긴 이름은 줄바꿈 또는 말줄임 규칙 적용
- 동명이인 정보는 필요한 사람에게만 표시

### 개인정보 안내

검색 및 최근 회의 목록의 범위와 접근 권한을 실제 기능에 맞게 설명합니다.

## 5.2 일정 필수 설정

참석자 선택 후 별도 단계에서 일정 필수 참석자를 지정합니다.

### 정책 선택

- `일정 필수 참석자 우선`
- `전원 일정 조건 충족`

### 용어 구분

**일정 필수:** 해당 참석자의 일정 가능 조건을 우선 고려한다는 의미

**참석 수락:** 실제 회의 참석 의사를 확인했다는 의미

두 개념을 동일하게 취급하지 않습니다.

### 참석자 행

`아바타 | 이름 | 일반 참석자/일정 필수 | 토글`

토글 상태는 색상뿐 아니라 텍스트로도 구분합니다.

### CTA

`완료 · 일정 필수 N명`

# 6. 일정 조율 진행 현황

## 6.1 핵심 문제

다음 상태가 섞이면 사용자가 실제 조율 진행도를 이해하기 어렵습니다.

- 참석자의 가능 시간 응답
- 캘린더 조회 결과
- 참석 수락
- 확인되지 않은 정보

## 6.2 상단 요약

**추천 구성**

> 2/3명 응답 완료

보조 정보:

> 응답 완료 2명 · 대기 1명

응답 마감일은 별도 행에 표시합니다.

## 6.3 참석자별 상태

각 참석자는 다음 두 축을 구분합니다.

**가능 시간 응답**

- 응답 완료
- 응답 대기
- 재확인 필요

**캘린더 정보**

- 조회됨
- 연결되지 않음
- 확인 불가

캘린더에서 비어 있다고 해서 참석을 수락한 것으로 표현하지 않습니다.

## 6.4 리마인드

데모 모드에서는 실제 알림이 발송되지 않음을 버튼 가까이에 표시합니다.

버튼 문구:

`응답 대기 1명에게 리마인드`

실제 발송하지 않는다면 처리 결과를 `데모 처리`로 명확히 표시합니다.

# 7. 추천 회의 시간 화면

## 7.1 추천 카드 구조

### 상단

- 현재 회의 조건 요약
- 추천 후보 개수
- 카드/후보 비교 전환

### 추천 카드

1. 추천 상태
2. 날짜
3. 시간
4. 필수 일정 조건 충족 여부
5. 참석 가능 응답 및 캘린더 확인 정보
6. 필요할 때만 추천 근거
7. 선택 컨트롤

### 정보 표현

`참석 가능 응답 2명`

`캘린더상 충돌 없음 1명`

`응답 대기·확인 불가 0명`

위 항목은 서로 중복되지 않는 집계 정의를 사용해야 합니다. 실제 데이터 모델에서 중복될 수 있다면 개별 축으로 표시하고 총합처럼 표현하지 않습니다.

## 7.2 추천 문구

사용하지 않을 표현:

- `3/3명 참석 확정`
- `전원 참석 가능`
- `확정 가능`

실제 참석 수락이 확인되지 않았다면 다음처럼 표현합니다.

- `일정 조건을 가장 잘 충족하는 시간`
- `일정 필수 조건 충족`
- `가능 시간 응답 2명`
- `캘린더상 충돌 없음 1명`

## 7.3 점수 표시

98점, 77점 등의 점수를 근거 없이 강조하지 않습니다.

점수를 유지하려면 계산 기준을 확인할 수 있어야 합니다.

우선순위는 다음과 같습니다.

1. 필수 일정 조건 충족
2. 확인된 일정 충돌
3. 가능 시간 응답
4. 선호 시간대 일치
5. 추가 정렬 기준

## 7.4 후보 비교

모바일에서 넓은 비교표를 그대로 축소하지 않습니다.

- 비교 항목은 3~4개로 제한
- 후보별 세로 카드 또는 간결한 비교 행 사용
- 상세 근거는 펼쳐서 확인
- 선택 상태를 명확히 표시
- 하단 CTA는 선택 전 비활성화

# 8. 내 회의 및 회의 상세 화면의 정렬 시스템

## 8.1 내 회의 목록

기존 문제:

- 왼쪽 날짜 박스와 오른쪽 정보의 수직 정렬이 불안정함
- 상태 배지가 제목과 경쟁함
- 카드마다 정보 시작 위치가 다름

### 공통 레이아웃

`날짜 블록 | 회의 정보 | 상태`

권장 기준:

- 날짜 블록: 48~52px 고정 너비
- 날짜 블록과 텍스트 간격: 12px
- 제목: 16px Semibold
- 날짜·시간·인원: 13~14px
- 상태: 작은 배지
- 추가 확인 사항: 별도 보조 행

날짜 블록은 카드 상단에 정렬하고, 회의 제목도 같은 시작선에 맞춥니다.

상태 배지 때문에 제목 영역이 지나치게 좁아지면 배지를 제목 아래로 이동합니다.

## 8.2 회의 상세 참석자 목록

공통 행 구조:

`아바타 | 이름·소속·상태`

- 아바타 너비 고정
- 이름과 소속 시작선 통일
- 상태는 이름 아래 별도 줄
- 알림 상태와 참석 응답 상태는 구분
- 배지가 2개 이상이면 공간에 따라 줄바꿈
- 모든 참석자 행에 동일한 내부 패딩 적용

## 8.3 상태 목록의 GUI

`알림 · 처리됨 (데모)`와 `응답 · 수락 대기` 같은 긴 문구를 작은 배지에 모두 넣지 않습니다.

추천 표현:

- 소제목: `알림`, `참석 응답`
- 상태 값: `데모 처리`, `수락 대기`

모바일에서는 짧은 상태 텍스트를 사용하고, 세부 내용은 상세 영역에서 제공합니다.

# 9. 재조율 후보 화면 개선

## 9.1 기존 문제

- `3명`, `2명`, `1명`처럼 여러 수치가 서로 다른 색상으로 표시됨
- `캘린더상 충돌 없음`은 다른 제목보다 길어 정렬이 깨짐
- 한 카드에 많은 상태를 한꺼번에 노출함
- 기존 응답을 새 일정에 적용할 수 있는지 이해하기 어려움

## 9.2 색상 규칙

기본 숫자는 모두 Navy로 통일합니다.

- 긍정적 조건 충족: 필요한 경우 그린 배지 1개
- 확인 필요: 앰버 또는 중립
- 실제 충돌: 레드 텍스트 또는 상태 배지
- 나머지 숫자: Navy

**한 카드 안에서 세 개의 숫자에 각각 다른 색상을 적용하지 않습니다.**

## 9.3 긴 항목명 해결

`캘린더상 충돌 없음`을 좁은 3열 통계 영역에 그대로 넣지 않습니다.

권장 방식:

### 상단 핵심 요약

- 가능 응답: 3명
- 일정 충돌: 1명

### 하단 보조 설명

- 캘린더 충돌 없음: 2명
- 새 응답 필요: 3명

또는 2열 통계 그리드를 사용합니다.

통계 제목은 2줄까지 허용하되 모든 셀의 제목 영역에 동일한 최소 높이를 부여합니다.

## 9.4 재조율 안내

기존 회의가 유지되는지 명확히 표시합니다.

추천 문구:

> 새 시간을 확정하기 전까지 기존 회의는 유지돼요.

새 후보에 기존 응답을 자동으로 재사용하지 않습니다.

응답 재사용 가능 여부는 실제 후보 시간 및 응답 데이터의 유효성에 따라 결정합니다.

## 9.5 재조율 확정 전

기존 일정과 새 일정을 비교합니다.

- 기존 날짜 및 시간
- 변경 날짜 및 시간
- 참석자 변경 여부
- 새 응답이 필요한 참석자
- 일정 충돌 및 확인 불가 상태

주요 CTA:

`새 일정으로 변경 확정`

# 11. 08 완료·처리 현황 화면 — 전면 구조 개선

**회의 저장 완료 → 회의 일정 → 후속 처리 현황 → 필요한 조치 → 다음 행동**

화면 상단에 충분한 여백을 둡니다.

> 디자인 리뷰 · 참석자 3명

- 제목: 22~24px Semibold
- 보조 정보: 14px
- 날짜 및 시간: 18px Semibold
- 중앙 정렬
- 요소 사이 충분한 간격
- 상단에서 초록색 배지를 추가로 반복하지 않음

### 문구 원칙

NODI 내부 저장 성공만 확인된 경우 `회의가 저장됐어요`라고 표현합니다.

- 조정하면 가능

# 13. 인터랙션 및 모바일 대응

## 13.1 바텀시트

- 상단 드래그 핸들
- 명확한 제목
- 닫기 버튼
- 콘텐츠 스크롤
- 하단 고정 CTA
- 닫기 시 변경사항 처리
- 키보드와 CTA 겹침 방지

바텀시트는 화면 전체를 덮는 느낌이 들지 않도록 내용에 따라 높이를 조절합니다.

긴 참석자 목록 등은 전체 높이에 가까운 시트를 사용할 수 있습니다.

## 13.2 키보드

iOS Safari와 설치형 앱에서 다음을 검증합니다.

- 입력창이 키보드 위로 올라오는지
- 마지막 채팅 메시지가 가려지지 않는지
- 하단 탭과 CTA가 중복되지 않는지
- 키보드가 열릴 때 불필요한 이중 스크롤이 생기지 않는지
- 키보드를 닫으면 원래 레이아웃으로 복귀하는지

`visualViewport`, `dvh`, safe-area 등 현재 기술 스택에 적합한 방법을 사용합니다.

## 13.3 하단 내비게이션

기존 3개 탭 유지:

- 회의 잡기
- 내 회의
- 받은 요청

회의 생성 중 집중 단계나 바텀시트에서는 하단 탭을 숨길 수 있습니다.

하단 탭을 숨기는 기준을 화면별로 일관되게 적용합니다.

## 13.4 로딩·오류·빈 상태

다음 상태를 모두 디자인합니다.

- AI 조건 해석 중
- AI 해석 실패
- 참석자 검색 결과 없음
- 참석자 선택 0명
- 응답 대기
- 추천 후보 없음
- 필수 참석자 일정 충돌
- 네트워크 오류
- 저장 중
- 저장 실패
- 저장 성공
- 알림 데모 처리 실패
- 재조율 후보 없음

단순히 빈 흰 화면이나 비활성화 버튼만 표시하지 않습니다.

# 20. 최종 판단 기준

이번 개선은 새로운 기능을 많이 추가하는 작업이 아닙니다.

**사용자가 더 적게 고민하고, 더 쉽게 선택하고, 더 정확하게 상태를 이해하도록 만드는 작업입니다.**

최종적으로 NODI는 다음 특성을 가져야 합니다.

- 처음 사용하는 사람도 시작하기 쉬움
- 선택과 자연어 입력이 자연스럽게 연결됨
- AI가 이해한 조건을 신뢰하고 수정할 수 있음
- 일정 조율 상태가 정확하게 전달됨
- 추천 이유를 이해할 수 있음
- 회의 저장과 외부 처리가 구분됨
- 모바일에서 답답하지 않고 정돈된 화면
- 아이콘보다 정보 위계가 돋보이는 GUI
- 화면 전체에서 일관된 정렬과 간격
- 기존 브랜드와 제품 정체성 유지

**기존 NODI를 유지하되, 실제 서비스 수준의 UX 완성도와 GUI 디테일을 갖추도록 구현하세요.**
