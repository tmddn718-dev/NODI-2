# NODI 모바일 UX/UI 통합 개선 명세서

**문서 버전:** 2.0  
**권장 파일명:** `NODI_Mobile_UXUI_Final_Improvement_Spec.md`  
**대상:** NODI 모바일 웹 및 iOS/Android 앱  
**목적:** 시각적 완성도, 정보 신뢰성, 사용성, 구현 일관성 개선  
**검토 범위:** 기존 23개 화면 통합 검증 내용, 추가 개선 시안 16개, 최근·자주 회의한 참석자 추천 요구사항

## 1. 프로젝트 목표

NODI는 사용자가 자연어로 회의 조건을 입력하면 AI가 조건을 구조화하고, 참석자의 일정 및 응답을 바탕으로 적합한 회의 시간을 추천하는 서비스다.

이번 개선은 기능을 새로 설계하는 전면 개편이 아니라, 기존 사용자 흐름과 브랜드를 유지하면서 다음 문제를 해결하는 데 목적이 있다.

1. 사용자가 현재 어떤 단계에 있는지 쉽게 이해한다.
2. 추천 결과의 근거와 불확실성을 정확히 구분한다.
3. 참석자 선택과 일정 필수 설정을 빠르게 완료한다.
4. 회의 확정과 외부 캘린더·알림 처리 상태를 혼동하지 않는다.
5. 모바일에서 버튼, 키보드, 스크롤, 바텀시트가 안정적으로 작동한다.
6. 모든 화면에서 일관된 타이포그래피와 간격 체계를 적용한다.

### 유지할 요소

- NODI 로고 및 기존 브랜드 아이덴티티
- 메인 블루 `#3654D4`
- 네이비 `#18243A`
- 밝은 배경 `#F5F7FB`
- 보라색 AI 보조 강조
- 자연어 기반 회의 생성
- 하단 3개 탭: 회의 잡기 / 내 회의 / 받은 요청
- 참석자별 응답과 캘린더 상태의 분리
- 일정 필수 참석자 우선 정책
- 기존 회의를 유지하는 재조율 방식

## 2. 최우선 수정 사항

### P0-01. 추천 상태와 실제 데이터의 모순 제거

**관찰된 문제**

재조율 후보 화면에서 `일정 필수 충족`으로 표시되지만, 같은 후보에 일정 필수 참석자의 캘린더 충돌이 표시되는 사례가 있다.

**개선 방향**

- 일정 필수 참석자의 후보별 조건 충족 여부를 서버 데이터 기준으로 판단한다.
- 일정 필수 참석자의 일정이 충돌하면 `일정 필수 충족`을 표시하지 않는다.
- 캘린더상 비어 있음과 참석 가능 응답은 서로 다른 근거로 표시한다.
- 참석 여부가 확인되지 않은 사람을 `참석 확정`으로 계산하지 않는다.
- 추천 조건을 만족하지 않는 후보는 제외하거나 `조건 미충족`으로 명확히 표시한다.

**권장 상태 용어**

| 상황 | 권장 표현 | 피해야 할 표현 |
|---|---|---|
| 가능 응답 제출 | 참석 가능 응답 | 참석 확정 |
| 캘린더에 충돌 없음 | 캘린더상 충돌 없음 | 참석 가능 확정 |
| 응답 없음 | 응답 대기 | 참석 불가 |
| 필수 참석자 조건 만족 | 일정 필수 조건 충족 | 전원 참석 확정 |
| 추천 조건 만족 | 조건 충족 후보 | 확정 가능한 시간 |
| 내부 회의 저장 완료 | NODI에 확정됨 | 모든 일정 처리 완료 |

**완료 기준**

동일 후보에서 `일정 필수 충족`과 `일정 필수 참석자 충돌`이 동시에 표시되지 않아야 한다.

### P0-02. 동일 회의의 데이터 일관성 확보

**관찰된 문제**

최종 검토와 완료 화면 사이에서 회의 날짜, 시간, 참석 인원이 달라지는 시안이 있다.

**개선 방향**

- 최종 검토 → 확정 → 완료 → 내 회의 → 회의 상세는 동일한 회의 ID와 확정 버전을 사용한다.
- 화면 이동 시 임의의 샘플 데이터로 대체하지 않는다.
- 회의 변경 시 이전 버전과 현재 버전을 명확히 구분한다.
- 개발용 시나리오가 다른 경우 테스트 데이터 세트를 분리한다.

**완료 기준**

같은 회의의 제목, 날짜, 시간, 길이, 참석자 수가 화면마다 일치해야 한다.

### P0-03. 고정 CTA와 스크롤 콘텐츠 분리

**관찰된 문제**

일부 화면에서 고정 버튼이 콘텐츠를 가리거나, 마지막 항목이 버튼 뒤에 걸쳐 보인다.

**개선 방향**

- 헤더, 스크롤 본문, 하단 CTA를 독립된 레이아웃 영역으로 구현한다.
- 본문 끝에는 CTA 높이와 안전 영역을 고려한 여백을 확보한다.
- 바텀시트 내부 스크롤과 배경 페이지 스크롤을 분리한다.
- 키보드가 열릴 때 입력창과 CTA가 가려지지 않도록 조정한다.
- iOS safe area와 Android 시스템 내비게이션 영역을 반영한다.

**완료 기준**

모든 화면에서 마지막 콘텐츠, 입력창, 주요 버튼에 정상 접근할 수 있어야 한다.

### P0-04. 회의 확정과 외부 작업 상태 분리

**개선 방향**

다음 상태를 각각 독립적으로 관리한다.

1. NODI 회의 확정
2. 외부 캘린더 반영
3. 참석자 알림 처리
4. 참석자 응답 상태

NODI에 회의가 저장되었다는 사실만으로 외부 캘린더에 반영되거나 참석자에게 알림이 전달된 것으로 표현하지 않는다.

데모 기능은 `데모 알림 처리`처럼 명확히 표시하고 실제 발송으로 오인시키지 않는다.

## 3. 모바일 디자인 시스템

아래 값은 기존 시안에서 측정한 확정 수치가 아니라, **개선 구현을 위한 권장 CSS 기준값**이다.

### 3.1 타이포그래피

| 역할 | 크기 | 행간 | 굵기 |
|---|---:|---:|---|
| 페이지 주요 제목 | 24px | 32px | 700 |
| 바텀시트 제목 | 22px | 30px | 700 |
| 중앙 모달 제목 | 22px | 30px | 700 |
| 섹션 제목 | 18px | 26px | 600 |
| 카드 주요 값 | 22~24px | 30~32px | 700 |
| 본문 | 16px | 24px | 400 |
| 강조 본문 | 16px | 24px | 600 |
| 보조 설명 | 14px | 21px | 400 |
| 상태 배지 | 12~14px | 18~20px | 600 |
| CTA 버튼 | 16px | 24px | 600 |

**적용 원칙**

- 한 화면에 24px 이상의 강조 텍스트를 과도하게 반복하지 않는다.
- 모달 제목과 본문은 최소 6px 정도의 크기 차이를 둔다.
- 긴 설명은 16px 본문과 14px 보조 설명으로 구분한다.
- 한글 본문의 행간은 글자 크기의 약 1.45~1.55배를 기본으로 한다.
- 상태 정보는 색상만으로 구분하지 않고 텍스트를 함께 제공한다.
- 작은 보조 텍스트도 충분한 명도 대비를 확보한다.

### 3.2 간격 체계

기본 4px 단위의 spacing scale을 사용한다.

| 토큰 | 값 | 사용처 |
|---|---:|---|
| space-1 | 4px | 아이콘과 짧은 텍스트 |
| space-2 | 8px | 라벨과 값, 버튼 사이 |
| space-3 | 12px | 카드 내 관련 요소 |
| space-4 | 16px | 리스트 행, 소규모 그룹 |
| space-5 | 20px | 카드 패딩 |
| space-6 | 24px | 화면 좌우 여백, 섹션 간격 |
| space-7 | 28px | 큰 폼 그룹 간격 |
| space-8 | 32px | 주요 섹션 구분 |

**공통 규칙**

- 화면 좌우 패딩: 20~24px
- 일반 카드 패딩: 20px
- 바텀시트 좌우 패딩: 24px
- 중앙 모달 좌우 패딩: 24px
- 카드 사이: 16px
- 섹션 사이: 24~32px
- 제목과 첫 콘텐츠 사이: 20~24px
- 카드 제목과 설명 사이: 8px
- 카드 내부 서로 다른 정보 그룹 사이: 16px

### 3.3 카드와 버튼

| 요소 | 권장값 |
|---|---|
| 일반 카드 radius | 16~20px |
| 중앙 모달 radius | 24px |
| 바텀시트 상단 radius | 24~28px |
| 주요 버튼 높이 | 52~56px |
| 보조 버튼 높이 | 48~52px |
| 선택 옵션 최소 높이 | 44~48px |
| 입력 필드 높이 | 52~56px |
| 터치 영역 최소 크기 | 44×44px |

버튼의 활성·비활성·로딩 상태를 시각적으로 구분하고, 비활성 이유가 중요한 경우 버튼 주변에 설명을 제공한다.

### 3.4 상태 색상

- 블루: 선택, 진행, 주요 행동
- 그린: 완료, 조건 충족, 성공
- 앰버: 일부 실패, 추가 확인 필요
- 레드: 충돌, 오류, 응답 불가
- 그레이: 대기, 미연결, 비활성
- 퍼플: AI 분석, 추천 근거

**주의:** 색상은 의미를 보조할 뿐, 상태의 유일한 표현 수단이 되어서는 안 된다.

## 4. 모달 및 바텀시트 개선

### 4.1 중앙 확인 모달

대상: 새 시간 조율 시작 확인

**문제**

- 제목과 본문 모두 크게 강조되어 시각적 위계가 약하다.
- 동일한 의미의 설명이 반복된다.
- 내용 대비 모달 높이가 커 보인다.

**권장 구조**

1. 아이콘
2. 제목
3. 핵심 설명
4. 보조 설명
5. 주요 행동
6. 취소 행동

**권장 카피**

제목: `새 시간 조율을 시작할까요?`

핵심 설명: `새 시간이 확정되기 전까지 기존 회의는 유지돼요.`

보조 설명: `기존 응답은 보관하고, 새 후보에 필요한 확인만 다시 요청합니다.`

주요 버튼: `새 시간 찾기 시작`

보조 버튼: `기존 회의로 돌아가기`

**권장 간격**

- 모달 좌우 패딩: 24px
- 상단 패딩: 24~28px
- 아이콘: 48~52px
- 아이콘 → 제목: 20px
- 제목 → 핵심 설명: 12px
- 핵심 설명 → 보조 설명: 8px
- 설명 → 버튼: 24px
- 버튼 간격: 8px
- 하단 패딩: 24px

**동작 규칙**

- 모달이 열리면 배경 스크롤을 잠근다.
- 닫기·취소 시 기존 회의에 변화가 없어야 한다.
- 주요 버튼을 반복 탭해도 재조율 작업이 중복 생성되지 않아야 한다.
- 스크린리더 포커스를 모달 내부로 이동한다.

### 4.2 바텀시트

대상: 회의 조건 수정, 참석자 선택, 일정 필수 설정

**권장 구조**

- 상단 드래그 핸들
- 제목 및 닫기 버튼
- 스크롤 가능한 콘텐츠
- 고정 CTA 영역
- 기기 안전 영역

**개선 원칙**

- 상단 핸들과 제목 사이에 충분한 여백을 둔다.
- 닫기 버튼의 터치 영역은 최소 44×44px로 확보한다.
- 바텀시트 내부에서만 콘텐츠가 스크롤되도록 한다.
- 선택된 항목이나 입력값이 키보드에 가려지지 않게 한다.
- 닫을 때 변경 내용이 있다면 저장 여부를 확인한다.
- 선택 완료 버튼은 선택 수와 다음 행동을 명확히 표시한다.

## 5. 화면별 상세 개선안

### 01. AI 조건 확인

**문제**

- AI 해석 결과 카드가 하단 입력창과 시각적으로 겹친다.
- 진행 단계 표시가 중복된다.
- AI가 추론한 값과 사용자가 직접 지정한 값의 차이가 약하다.

**개선**

- AI 조건 요약 카드를 스크롤 가능한 영역에 완전히 표시한다.
- 각 항목에 `AI 해석` 또는 `직접 설정` 상태를 일관되게 제공한다.
- 날짜가 잘못 해석된 경우 수정 행동을 명확히 제공한다.
- `확인 전` 상태에서는 다음 단계로 넘어가기 전에 조건 검토를 유도한다.
- 상단 진행 표시는 단계 수와 현재 단계 명칭이 일치하도록 한다.

### 02. 회의 조건 수정

**문제**

- 5개 길이 옵션이 한 줄에 과밀하다.
- 날짜·시간대·참석 방식 그룹의 구분이 약하다.
- 변경 사항이 없을 때 되돌리기 버튼의 역할이 모호하다.

**개선**

- 회의 길이 옵션을 화면 폭에 맞게 재배치한다.
- 날짜 선택과 기간 선택을 명확히 구분한다.
- 선택한 날짜 범위를 요약해 보여준다.
- 오전·오후·상관없음의 실제 시간 범위를 설명한다.
- 변경이 없으면 저장 CTA를 비활성화하고 이유를 표시한다.
- 변경 사항이 있을 때만 되돌리기를 활성화한다.

### 03. 참석자 선택 및 추천

**문제**

- 선택 칩이 늘어나면서 추천 목록이 아래로 밀린다.
- 최근 회의한 사람의 메타데이터가 길다.
- 자주 함께 회의한 사람 섹션이 화면 아래에 가려질 수 있다.
- 동명이인 구분 정보가 부족할 수 있다.

**개선 구조**

1. 검색 필드
2. 팀 필터
3. 선택된 참석자 요약
4. 최근 함께 회의한 사람
5. 자주 함께 회의한 사람
6. 전체 참석자 검색 결과

**최근 함께 회의한 사람**

- 사용자가 실제로 참여한 NODI 회의 기록을 기준으로 한다.
- 취소된 회의는 추천 기준에서 제외한다.
- 최근 회의일을 보조 정보로 제공한다.
- 선택된 사람은 목록에서 선택 상태를 유지한다.

**자주 함께 회의한 사람**

- 일정 기간의 공동 회의 횟수를 기준으로 정렬한다.
- 기간과 횟수 기준은 구현 시 명시적으로 정의한다.
- 동일한 사람이 최근 목록에도 있으면 중복 표시를 줄인다.
- 실제 기록이 부족한 경우 임의의 추천을 생성하지 않는다.

**추천 행 구조**

- 체크박스
- 아바타
- 이름
- 팀 또는 직무
- 최근 회의일 또는 추천 근거
- 동명이인 식별 정보

**추가 개선**

- 선택 칩은 최대 2줄 표시 후 접을 수 있도록 한다.
- `3명 선택됨`을 항상 확인할 수 있게 한다.
- 선택 상태는 검색·필터 변경 후에도 유지한다.
- 추천 목록이 비어 있을 때는 전체 검색을 안내한다.
- 개인별 회의 기록은 접근 권한과 개인정보 기준을 준수한다.

### 04. 일정 필수 설정

**문제**

- 정책 설명이 여러 영역에 반복된다.
- 개인별 행이 너무 높다.
- `일정 필수`라는 표현이 중복된다.

**개선**

- 정책 선택 카드 2개는 유지한다.
- 일정 필수의 의미는 상단에서 한 번만 설명한다.
- 개인별 행은 이름·상태·스위치 중심으로 간결하게 구성한다.
- 스위치 선택 시 해당 사람의 상태가 즉시 갱신된다.
- 일정 필수 설정은 참석 수락 여부와 무관함을 설명한다.

**권장 문구**

`일정 필수로 지정한 사람의 일정 조건을 우선 충족하는 시간을 추천해요. 참석 수락을 의미하지는 않아요.`

### 05. 조율 진행 현황

**문제**

- 응답 제출 수와 후보별 가능 여부 요약이 한 영역에 섞여 있다.
- 응답 대기와 재확인 필요의 차이가 약하다.

**개선**

- 상단: 제출 현황
- 중단: 참석자별 응답 및 캘린더 조회 상태
- 하단: 추천 시간 보기

**권장 요약**

`응답 제출 2/3명`

`제출 2명 · 대기 1명`

후보별 가능 여부는 별도 섹션에서 제공한다.

### 06. 추천 회의 시간

**문제**

- 추천 제목과 후보 카드에서 날짜·시간이 반복된다.
- `확정 가능`이 실제 참석 확정처럼 읽힐 수 있다.
- 추천 근거의 위계가 복잡하다.

**개선**

- 상단 제목: `추천 후보 3개를 찾았어요`
- 후보 카드에서는 시간과 조건 충족 여부를 가장 강조한다.
- 가능 응답, 캘린더 상태, 응답 대기를 분리한다.
- AI 추천 이유는 1~2문장으로 요약한다.
- 비교 화면에서는 핵심 차이만 먼저 보여준다.
- 추천 점수를 사용한다면 계산 근거를 설명할 수 있어야 한다.

### 07. 최종 검토

**문제**

- 외부 캘린더와 알림 처리의 의미가 모호하다.
- 연결되지 않은 기능이 단순 비활성 스위치처럼 보인다.

**개선**

- 회의 제목·날짜·시간·참석자·일정 필수 설정을 최종 확인한다.
- 외부 캘린더 미연결 상태를 명확히 표시한다.
- 알림이 데모 처리인지 실제 발송인지 구분한다.
- 확정 버튼 바로 위에 확정 후 처리 범위를 설명한다.

### 08. 완료 및 처리 현황

**문제**

- 성공 메시지와 경고가 동시에 크게 강조된다.
- 외부 작업 상태 카드가 하단 CTA에 가려질 수 있다.

**개선**

- 1순위: NODI 회의 확정 성공
- 2순위: 외부 작업 처리 현황
- 3순위: 실패 작업 재시도
- 4순위: 회의 상세 이동

**권장 제목**

`NODI에 회의가 확정됐어요`

**권장 설명**

`외부 캘린더 반영과 참석자 알림은 아래에서 별도로 확인할 수 있어요.`

### 09. 내 회의

**개선**

- 회의명, 날짜·시간, 참석 인원, 상태를 명확히 구분한다.
- 외부 처리 문제가 있으면 별도 주의 표시를 제공한다.
- 예정 / 조율 중 / 지난·취소 탭의 상태 기준을 통일한다.
- 회의가 없는 경우 빈 상태 안내와 회의 생성 CTA를 제공한다.

### 10. 회의 상세

**문제**

- 상태 설명이 길다.
- 알림 실패 재시도 버튼이 지나치게 큰 영역을 차지한다.
- 하단 재조율 버튼이 일부 가려질 수 있다.

**개선**

- 상태는 `NODI 회의`, `캘린더`, `알림`으로 구분한다.
- 상태 설명은 짧게 표시하고 상세 내용은 펼쳐본다.
- 실패 알림은 실패 대상과 원인을 보여준다.
- 재시도 후 처리 결과를 갱신한다.
- 재조율 CTA가 화면 하단에서 안전하게 표시되도록 한다.

### 11. 재조율 시작 모달

**개선**

- 제목 22px / 30px
- 핵심 설명 16px / 24px
- 보조 설명 14px / 21px
- 반복되는 문장 제거
- 주요 버튼과 보조 버튼의 시각적 위계 강화
- 기존 회의 유지 사실을 가장 먼저 전달

### 12. 재조율 후보

**문제**

- 일정 필수 충족 여부와 캘린더 충돌의 모순
- 기존 응답과 새 후보에 대한 응답의 관계가 복잡함

**개선**

- 후보별 유효한 응답만 반영한다.
- 기존 응답을 재사용할 수 있는 조건을 명시한다.
- 새 확인이 필요한 인원을 구분한다.
- 일정 필수 조건 미충족 후보는 추천 제외 또는 경고 표시한다.
- 근거와 충돌 대상자를 명확히 제공한다.

### 13. 변경 내용 검토

**문제**

- 모바일 3열 비교표의 줄바꿈이 많다.
- 외부 처리 관련 정보가 읽기 어렵다.

**개선**

- 날짜·시간은 변경 전 → 변경 후 카드로 비교한다.
- 참석자 수와 변경 여부는 별도 행으로 표시한다.
- 새 응답 필요 인원을 강조한다.
- 외부 작업의 실제 처리 범위를 명확히 표시한다.
- 확정 전 최신 응답과 기존 회의 버전을 다시 확인한다.

### 14. 받은 요청

**개선**

- 행동이 필요한 요청을 우선 노출한다.
- 재확인 필요 / 응답 필요 / 제출 완료 / 확정된 회의를 구분한다.
- 완료된 요청은 접거나 지난 요청으로 이동할 수 있게 한다.
- 요청 카드 전체를 눌러 상세 화면으로 이동하도록 한다.

### 15. 참석 가능 시간 응답

**문제**

- 선택 버튼이 커서 화면이 길어진다.
- 개발용 제출 ID가 노출된다.
- 하단 CTA가 입력 영역을 가릴 수 있다.

**개선**

- 후보별 선택 버튼 높이를 44~48px로 통일한다.
- 임시 저장 상태를 짧게 표시한다.
- 모든 후보에 응답했는지 명확히 안내한다.
- 제출 ID는 일반 사용자 화면에서 제거한다.
- 중복 제출을 방지한다.
- 제출 후 결과를 확인할 수 있게 한다.

### 16. 조건 변경된 요청

**문제**

- 경고 문구가 길다.
- `기록만 보관`의 의미가 모호하다.

**개선 문구**

제목: `회의 시간이 변경됐어요`

설명: `새 후보가 추가되어 다시 확인이 필요해요.`

상태:
- `이전 응답 유지`
- `새 응답 필요`

CTA: `변경된 후보 확인하기`

## 6. 공통 UX Writing 규칙

### 6.1 짧고 명확한 문장

- 한 문장에 한 가지 핵심 정보만 담는다.
- 시스템 내부 용어보다 사용자 행동을 기준으로 작성한다.
- 설명은 가능한 한 2줄 이내로 구성한다.
- 긴 설명은 상세 보기나 도움말로 이동한다.

### 6.2 상태와 행동을 구분

상태: `응답 대기`

행동: `리마인드 보내기`

상태: `알림 일부 실패`

행동: `실패한 알림 다시 처리`

상태: `캘린더 연결 안 됨`

행동: `캘린더 연결하기`

### 6.3 권장 용어 통일

| 기존 표현 | 권장 표현 |
|---|---|
| 확정 가능 | 조건 충족 |
| 3/3명 참석 가능 | 가능 응답 2명 · 캘린더상 충돌 없음 1명 |
| 기록만 보관 | 이전 응답 유지 또는 새 응답 필요 |
| 데모 처리 예정 | 데모 알림 처리 예정 |
| 바뀐 조건이 없어요 | 변경된 내용이 없어요 |
| 재조율 그만두고 기존 일정 유지 | 기존 회의 유지 |
| 새 시간 조율하기 | 새 시간 찾기 |

용어는 실제 기능과 데이터 상태에 맞게 최종 확정한다.

## 7. 인터랙션 및 접근성

### 7.1 터치와 선택

- 모든 주요 터치 대상은 최소 44×44px를 확보한다.
- 체크박스와 라디오 버튼은 행 전체를 눌러도 선택 가능하게 한다.
- 선택 상태는 색상과 체크 표시로 함께 표현한다.
- 스위치의 현재 상태를 스크린리더가 읽을 수 있어야 한다.

### 7.2 모달과 포커스

- 모달이 열리면 포커스를 모달로 이동한다.
- 모달을 닫으면 이전에 누른 버튼으로 포커스를 되돌린다.
- 배경 페이지는 모달이 열려 있는 동안 조작되지 않아야 한다.
- 중요한 작업의 취소·확정은 실수로 발생하지 않도록 한다.

### 7.3 키보드

- 키보드가 열릴 때 입력 필드가 가려지지 않아야 한다.
- 입력 중에는 하단 탭을 숨기거나 적절히 조정한다.
- iOS Safari의 visual viewport 변화에 대응한다.
- Android 뒤로 가기 동작이 모달·시트·화면 이동과 일관되게 작동해야 한다.

### 7.4 로딩과 오류

- AI 조건 해석 중 로딩 상태를 제공한다.
- 추천 재계산 중 이전 추천을 새 결과처럼 표시하지 않는다.
- 네트워크 오류 시 입력 내용과 선택값을 유지한다.
- 재시도 가능한 작업과 재시도 불가능한 작업을 구분한다.

### 모바일 사용성

- [ ] 모든 콘텐츠를 끝까지 스크롤할 수 있다.
- [ ] 고정 CTA가 콘텐츠를 가리지 않는다.
- [ ] 키보드가 입력창을 가리지 않는다.
- [ ] 바텀시트와 배경 페이지의 스크롤이 충돌하지 않는다.
- [ ] 안전 영역을 침범하지 않는다.
- [ ] 작은 화면에서도 버튼을 정상적으로 누를 수 있다.

### 참석자 선택

- [ ] 최근 함께 회의한 사람이 정상 노출된다.
- [ ] 자주 함께 회의한 사람이 정상 노출된다.
- [ ] 추천 목록에 중복 인원이 불필요하게 반복되지 않는다.
- [ ] 동명이인을 구분할 수 있다.
- [ ] 검색과 필터 변경 후에도 선택이 유지된다.
- [ ] 선택 해제와 전체 해제가 정상 작동한다.

### 재조율

- [ ] 재조율 시작 시 기존 회의가 유지된다.
- [ ] 새 후보가 확정되기 전까지 기존 회의가 변경되지 않는다.
- [ ] 기존 응답과 새 응답을 정확히 구분한다.
- [ ] 변경 내용 검토에서 이전 일정과 새 일정을 비교할 수 있다.
- [ ] 새 일정 확정 시 회의 상태가 일관되게 갱신된다.

## 11. 사용자 테스트 계획

정량 사용 데이터가 없다면 개선 전후 프로토타입을 활용해 정성 검증을 진행한다.

### 테스트 과제

1. 자연어로 회의 조건 입력 후 AI 해석 결과 수정하기
2. 최근 함께 회의한 사람 중 3명 선택하기
3. 선택한 사람 중 1명을 일정 필수로 지정하기
4. 추천 후보의 참석 가능 근거 확인하기
5. 회의를 확정하고 외부 알림 실패 여부 찾기
6. 기존 회의를 유지하면서 새 시간 재조율하기
7. 변경된 회의 요청에 다시 응답하기

### 기록할 항목

- 과제 완료 여부
- 과제 완료 시간
- 잘못된 선택 횟수
- 도움 요청 횟수
- 상태 의미를 정확히 설명했는지
- 사용자가 혼란을 느낀 문구
- 스크롤·터치·키보드 사용 중 발생한 문제

### 결과 해석 원칙

- 테스트 전후 차이를 기록한다.
- 실제 측정하지 않은 개선율은 작성하지 않는다.
- 소규모 테스트는 통계적 효과 입증보다 문제 발견과 개선 방향 검증에 활용한다.
- 사용자 발화와 행동을 함께 기록한다.
- 수정 후 동일 과제를 재검증한다.

## 12. Claude 개발 전달용 최종 지시사항

NODI의 기존 브랜드, 로고, 주요 사용자 흐름은 유지한다.

이번 작업은 전면 리디자인이 아니라 기존 모바일 UI의 완성도를 높이는 개선 작업이다.

다음 순서로 구현한다.

1. 추천 상태와 실제 데이터의 모순을 수정한다.
2. 동일 회의 정보가 화면 간 일치하도록 한다.
3. 확정·캘린더·알림·참석 응답 상태를 분리한다.
4. 고정 CTA와 스크롤 콘텐츠가 겹치지 않도록 수정한다.
5. 본 명세서의 타이포그래피·간격·카드·버튼 규칙을 공통 컴포넌트에 적용한다.
6. 모달과 바텀시트의 제목·본문·보조 설명 위계를 정리한다.
7. 참석자 선택에 최근·자주 함께 회의한 사람 추천을 반영한다.
8. 추천·재조율·변경 비교 화면의 정보 밀도를 낮춘다.
9. 중복 설명과 개발용 문구를 제거한다.
10. iOS 및 Android 모바일 환경에서 QA를 진행한다.

**구현 결과물에 포함할 내용**

- 변경한 화면 및 컴포넌트 목록
- 적용한 디자인 토큰
- 상태 모델 변경 사항
- 해결한 UX 문제
- 모바일 QA 결과
- 미해결 항목과 후속 개선 과제

## 13. 최종 완료 기준

이번 개선이 완료되었다고 판단하려면 다음 조건을 충족해야 한다.

**시각적 완성도**

모든 화면에서 제목, 본문, 카드, 상태 배지, 버튼의 시각적 위계가 일관된다.

**실제 사용성**

사용자가 회의 생성부터 확정, 응답, 재조율까지 진행하면서 현재 상태와 다음 행동을 이해할 수 있다.

**정보 신뢰성**

추천 근거와 참석 상태가 실제 데이터와 일치하며, 확인되지 않은 정보를 확정된 사실처럼 표현하지 않는다.

**모바일 안정성**

작은 화면, 키보드 표시, 긴 목록, 바텀시트, 고정 CTA 환경에서도 모든 핵심 작업을 수행할 수 있다.

**구현 일관성**

동일한 상태와 컴포넌트가 화면마다 다른 의미나 스타일로 표현되지 않는다.

## 14. 최종 권장 방향

NODI의 다음 개선 단계는 기능 추가보다 **정보 신뢰성, 시각적 위계, 모바일 조작성의 일관성 확보**에 집중해야 한다.

가장 중요한 작업 순서는 다음과 같다.

**상태 데이터 정합성 수정 → 레이아웃 충돌 해결 → 타이포그래피 및 간격 통일 → 정보 밀도 축소 → 참석자 추천 고도화 → 사용자 테스트**

이 순서를 따르면 사용자가 회의 조율 과정에서 느끼는 불확실성을 줄이고, NODI의 AI 추천 결과를 더 명확하고 신뢰할 수 있게 전달할 수 있다.
