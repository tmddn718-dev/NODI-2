# NODI — 23개 화면 통합 UX/UI 검증 및 최종 개선 명세서

**문서 버전:** 2.0  
**기준:** 기존 20개 화면에 대한 이전 검토 내용 + 추가 3개 화면 + 참석자 추천 기능 요구사항  
**목적:** 모바일 중심의 회의 생성·조율·확정·재조율 경험 개선  
**권장 파일명:** `NODI_23_Screens_UXUI_Validation_and_Improvement.md`

> **검증 범위 안내:** 추가된 3개 화면은 이미지에서 직접 확인한 내용을 기준으로 평가했다. 기존 20개 화면은 이전 대화에서 확인한 화면 및 개선 논의를 통합했다. 현재 문서 작성 시점에 20개 원본 이미지를 모두 다시 대조한 것은 아니므로, 전체 23개 화면의 픽셀 단위 검수나 실제 기능 동작 검증이 완료되었다는 의미는 아니다.

## 1. Executive Summary

NODI는 사용자가 자연어로 회의 조건을 입력하면 AI가 이를 구조화하고, 참석자의 일정 및 응답을 근거로 회의 시간을 추천한 뒤, 사용자의 명시적 승인으로 확정하는 서비스다.

이번 통합 검토에서 가장 중요한 개선 과제는 다음과 같다.

| 우선순위 | 개선 영역 | 핵심 문제 | 권장 방향 |
|---|---|---|---|
| P0 | AI 조건 확인 | AI가 해석한 조건과 사용자가 승인한 조건의 경계 | 구조화된 조건 확인 단계 명확화 |
| P0 | 참석자 역할 | 참석자 선택과 일정 필수 지정의 혼동 | 선택과 필수 설정 분리 |
| P0 | 일정 상태 | 캘린더 빈 시간, 응답, 수락, 확정의 혼용 | 데이터 출처별 상태 표현 |
| P0 | 추천 근거 | 가능 인원과 확정 가능 여부의 과장 위험 | 확인된 사실·미확인 정보 분리 |
| P0 | 최종 확정 | 후보 선택과 실제 확정의 혼동 | 최종 검토 및 서버 재검증 |
| P0 | 회의 상세 | 내부 저장·외부 반영·알림 결과의 혼동 | 독립적인 처리 상태 |
| P0 | 재조율 | 기존 일정과 새 후보의 관계가 불명확할 위험 | 기존 일정 유지, 새 후보 별도 관리 |
| P0 | 재조율 응답 | 기존 응답의 재사용 가능 범위가 모호함 | 후보별 응답 유효성 검증 |
| P0 | 모바일 안정성 | 키보드·시트·고정 CTA의 화면 충돌 | 실기기 기반 레이아웃 검증 |
| P1 | 참석자 추천 | 반복적인 참석자 검색 부담 | 최근·자주 함께 회의한 사람 추천 |
| P1 | 후보 비교 | 모바일에서 정보 밀도가 높음 | 차이 중심 비교 |
| P1 | 실패 복구 | 실패 후 사용자가 해야 할 일이 불분명함 | 실패 대상·원인·재시도 결과 안내 |

**제품 원칙:** AI는 해석과 설명을 돕고, 일정 가능 여부·추천·확정은 검증 가능한 데이터와 규칙으로 처리한다.

## 2. 권장 최종 사용자 흐름

### 2.1 신규 회의 생성

1. 회의 잡기 진입
2. 자연어 또는 선택형 입력
3. AI가 이해한 회의 조건 확인
4. 회의 기간·시간·길이 수정
5. 참석자 선택
6. 일정 필수 참석자 지정
7. 참석 가능 시간 수집
8. 추천 후보 확인
9. 후보 비교 및 선택
10. 최종 확정 전 검토
11. 사용자 승인
12. NODI 내부 저장
13. 외부 캘린더·알림 처리 결과 표시
14. 회의 상세에서 후속 관리

### 2.2 확정된 회의 재조율

1. 회의 상세에서 `새 시간 조율하기` 선택
2. 기존 일정 유지 정책 확인
3. 재조율 시작
4. 새 후보와 참석자별 응답 상태 확인
5. 필요한 후보에 대해서만 재확인 요청
6. 새 후보 선택
7. 기존 일정과 변경 예정 일정 비교
8. 최신 일정·응답 재검증
9. 사용자 승인
10. 새 일정으로 변경 처리
11. 변경 결과 및 알림 상태 표시

**핵심:** 재조율 시작은 기존 회의 취소가 아니다. 새 일정이 유효하게 확정되기 전까지 기존 일정이 유지되어야 한다.

## 3. 기존 화면 흐름 통합 개선안

### P0-01. AI 대화와 구조화된 조건 연결

**문제**

자연어 입력 후 AI가 어떤 조건을 추출했는지 사용자가 명확히 이해하지 못하면, 잘못된 회의 조건으로 다음 단계에 진입할 수 있다.

**개선안**

- AI 응답 다음에 `이렇게 이해했어요` 카드를 제공한다.
- 회의 제목, 목적, 길이, 기간, 선호 시간대, 참석자를 구조화해 표시한다.
- 각 항목을 직접 수정할 수 있도록 한다.
- 확정되지 않은 조건은 `미정`으로 표시한다.
- 사용자가 확인한 조건만 다음 단계의 기준 데이터로 사용한다.

**권장 문구**

- `이 조건으로 시간을 찾아볼까요?`
- `아직 정하지 않은 조건이 있어요. 지금 정하거나 나중에 추가할 수 있어요.`

### P0-02. 날짜 범위와 특정 날짜 구분

**문제**

`다음 주`라는 기간과 `11월 17일`이라는 특정 날짜가 동일한 선택 상태처럼 표현되면 검색 범위를 오해할 수 있다.

**개선안**

- 검색 기간과 선호 날짜를 별도로 관리한다.
- `11월 16일~20일 중`과 `11월 17일 선호`를 구분한다.
- 오전·오후·상관없음 선택의 의미를 명확히 한다.
- 기간 또는 길이를 바꾸면 기존 추천이 더 이상 유효하지 않음을 알린다.

### P0-03. 참석자 선택과 일정 필수 설정 분리

**문제**

참석자를 추가하는 행위와 일정 필수 참석자로 지정하는 행위가 같은 화면에서 충분히 구분되지 않으면 실수할 수 있다.

**개선안**

- 참석자 선택 후 일정 필수 여부를 설정하는 흐름을 유지한다.
- 별표 아이콘만으로 의미를 전달하지 않는다.
- `일정 필수`라는 텍스트를 함께 제공한다.
- 일정 필수의 의미를 `이 사람의 일정 조건이 충족되어야 후보로 추천해요`로 설명한다.
- 일정 필수는 참석 수락 또는 참석 확정을 뜻하지 않는다.

### P0-04. 참석 가능 상태 구분

다음 상태는 서로 바꿔 사용할 수 없다.

| 상태 | 의미 |
|---|---|
| 일정 충돌 없음 | 조회 가능한 캘린더상 충돌이 없음 |
| 참석 가능 응답 | 참석자가 해당 후보에 가능하다고 응답 |
| 참석 불가 응답 | 참석자가 해당 후보에 불가하다고 응답 |
| 응답 대기 | 아직 응답하지 않음 |
| 일정 확인 불가 | 권한·연결·데이터 문제로 확인 불가 |
| 참석 수락 | 실제 초대에 대해 수락한 상태 |
| NODI 확정 | NODI 내부에서 회의가 확정된 상태 |

**금지할 표현**

- 캘린더만 비어 있는데 `참석 확정`
- 미응답자를 포함해 `전원 참석 가능`
- 외부 초대가 발송되지 않았는데 `초대 완료`

### P0-05. 추천 후보의 신뢰성 개선

**개선안**

각 추천 카드에는 다음 정보를 우선 표시한다.

1. 날짜와 시간
2. 일정 필수 조건 충족 여부
3. 참석 가능 응답 인원
4. 일정 충돌이 없는 인원
5. 응답 대기·확인 불가 인원
6. 추천 이유
7. 다음 행동

점수는 보조 정보로 제공하고, 사용자가 이해할 수 있는 근거를 먼저 보여준다.

**권장 문구**

- `현재 확인된 정보에서 가장 적합한 후보예요.`
- `일정 필수 조건은 충족했지만 1명의 응답이 필요해요.`
- `캘린더상 충돌은 없지만 참석 수락은 확인되지 않았어요.`

### P0-06. 조건 변경 시 추천 무효화

회의 기간, 길이, 참석자, 일정 필수 설정이 바뀌면 이전 추천을 그대로 유지하지 않는다.

- 기존 추천을 최신 조건과 비교한다.
- 영향을 받는 후보를 무효화한다.
- 재계산 필요 이유를 설명한다.
- 이전 후보를 최신 추천인 것처럼 확정할 수 없도록 한다.

### P0-07. 최종 확정 단계

후보를 선택했다고 곧바로 확정 처리하지 않는다.

최종 검토 화면에는 다음 항목이 필요하다.

- 회의 제목·날짜·시간
- 참석자 및 일정 필수 참석자
- 최신 일정 확인 결과
- 미응답 또는 확인 불가 인원
- NODI 내부 저장 예정 상태
- 외부 캘린더 반영 가능 여부
- 참석자 알림 처리 예정 상태

사용자가 명시적으로 `회의 확정하기`를 눌러야 확정한다.

## 4. 추가 화면 ① — 회의 상세 검증

### 4.1 화면에서 확인된 내용

- 상단 회의 상태 `확정됨`
- 회의 제목 `새 회의`
- `11월 23일 (월) 오전 10:00–11:00`
- NODI 회의 상태 `확정됨`
- 캘린더 반영 `연결 안 됨`
- 참석자 알림 `일부 실패`
- `발송됨 5 · 실패 1 · 데모 발송`
- `실패한 1건만 다시 보내기`
- `새 시간 조율하기`
- 참석자별 `주최자`, `수락 대기` 상태

### 4.2 긍정적인 점

NODI 내부 확정, 캘린더 반영, 참석자 알림을 별도 행으로 구분한 구조는 적절하다.

실패한 알림 1건만 재시도할 수 있도록 한 것도 전체 재발송으로 인한 중복 알림 위험을 줄이는 방향이다.

### 4.3 개선 과제

**A. `확정됨`의 범위를 더 명확히 한다.**

상단의 `확정됨`은 NODI 내부 상태임을 상세 영역에서 분명히 설명해야 한다.

권장 문구:

`NODI에 회의가 확정되어 저장됐어요. 외부 캘린더 반영과 참석자 응답은 별도로 확인해 주세요.`

**B. 데모 발송과 실제 발송을 혼동하지 않도록 한다.**

현재 화면에는 `발송됨 5 · 실패 1 · 데모 발송`이 함께 표시된다.

실제 전송이 발생하지 않는 데모라면 다음처럼 표현한다.

`데모 알림 처리: 성공 5건 · 실패 1건`

재시도 버튼도 실제 발송처럼 오인되지 않도록 데모 환경에서는 `실패한 데모 알림 1건 다시 처리`처럼 구분할 수 있다.

**C. 알림 실패 대상과 재시도 결과를 확인할 수 있어야 한다.**

- 실패 대상 확인
- 실패 원인 또는 확인 가능한 오류 범위
- 마지막 시도 시각
- 재시도 중 상태
- 재시도 성공·실패 결과
- 중복 발송 방지

**D. 참석자 수락 대기와 알림 전달 상태를 분리한다.**

`수락 대기`는 초대 발송 성공을 의미하지 않는다.

참석자 상세에서는 필요 시 `알림 상태`와 `응답 상태`를 구분한다.

**E. 회의 제목 `새 회의`는 수정 가능하도록 한다.**

기본 제목을 허용하더라도 회의 목적을 구분하기 어려울 수 있으므로 제목 편집 진입점을 제공한다.

## 5. 추가 화면 ② — 재조율 시작 확인 검증

### 5.1 화면에서 확인된 내용

확인 다이얼로그 제목:

`새 시간 조율을 시작할까요?`

주요 안내:

- 기존 회의를 취소하지 않음
- 새 시간이 확정될 때까지 기존 일정과 초대 유지
- 기존 응답은 삭제하지 않음
- 영향받는 후보만 재확인 요청

버튼:

- `닫기`
- `재조율 시작`

### 5.2 긍정적인 점

기존 일정을 유지한다는 정책을 재조율 시작 전에 안내하는 점은 좋다.

사용자가 재조율을 시작하는 행위를 회의 취소로 오해하지 않도록 돕는다.

### 5.3 개선 과제

**A. 안내 문구를 간결하게 만든다.**

권장 문구:

`새 시간이 확정되기 전까지 기존 회의는 유지돼요.`

보조 문구:

`기존 응답은 보관하고, 새 후보에 필요한 확인만 다시 요청해요.`

**B. 기존 응답 보관과 새 후보에서의 유효성을 구분한다.**

기존 응답을 삭제하지 않는 것은 맞지만, 기존 시간에 대한 응답을 새 시간에 그대로 적용할 수 있다는 의미는 아니다.

응답은 후보 시간에 연결된 기록으로 보관해야 한다.

**C. 다이얼로그의 행동을 명확히 한다.**

- 취소: `기존 회의로 돌아가기`
- 확인: `새 시간 찾기 시작`

현재의 `닫기`도 기능상 가능하지만, 사용자가 어떤 상태로 돌아가는지 더 구체적으로 설명하는 편이 좋다.

**D. 접근성 검증**

- 다이얼로그 제목과 설명 연결
- 열릴 때 포커스 이동
- 닫을 때 원래 버튼으로 포커스 복귀
- 배경 스크롤 방지

## 6. 추가 화면 ③ — 재조율 후보 검증

### 6.1 화면에서 확인된 내용

기존 확정 일정:

`11월 23일 (월) 오전 10:00–11:00`

새 후보 1:

- `11월 25일 (수) 오후 2:00–3:00`
- `참여 가능 4/5명`
- `일정 필수 충족`
- `응답 유지 3명`
- `재확인 필요 이도윤`

새 후보 2:

- `11월 26일 (목) 오전 10:00–11:00`
- `참여 가능 3/5명`
- `일정 필수 충족`
- `응답 유지 2명`
- `재확인 필요 정유나`
- `참석 어려움 박지훈`

하단:

- 후보 미선택 상태의 비활성 CTA
- `재조율 그만두고 기존 일정 유지`

### 6.2 긍정적인 점

기존 일정과 새 후보를 시각적으로 구분했다.

재조율을 중단하고 기존 일정을 유지하는 경로도 명확하다.

후보마다 참여 가능 인원, 일정 필수 충족 여부, 재확인 대상이 표시되는 구조는 적절하다.

### 6.3 핵심 검증 과제

**A. `응답 유지`의 정확한 의미를 정의한다.**

기존 회의의 응답을 새 후보로 그대로 복사해서는 안 된다.

`응답 유지`는 해당 후보 시간에 대해 이미 수집한 유효한 응답이 존재하는 경우에만 사용할 수 있다.

그 외에는 다음처럼 표현한다.

- `기존 응답 기록 보관`
- `새 시간 응답 필요`
- `해당 후보에 대한 응답 확인됨`

**B. `참여 가능 4/5명`의 집계 기준을 명시한다.**

가능 인원에 포함되는 데이터가 무엇인지 정의해야 한다.

캘린더상 충돌 없음과 명시적 참석 가능 응답을 단일 숫자로 합산하면 사용자가 오해할 수 있다.

권장 표시 예시:

`참석 가능 응답 3명 · 캘린더상 충돌 없음 1명 · 재확인 필요 1명`

실제 데이터에 맞게 수치를 계산해야 하며 예시 숫자를 화면에 고정해서는 안 된다.

**C. `일정 필수 충족`의 판단 근거를 제공한다.**

필수 참석자의 일정 충돌이 없는 것인지, 명시적 가능 응답이 있는 것인지 구분해야 한다.

**D. 후보 선택 이후에도 바로 변경하지 않는다.**

선택한 후보는 변경 검토 단계로 이동해야 한다.

최종 검토에서 다음 내용을 비교한다.

| 항목 | 기존 회의 | 변경 예정 |
|---|---|---|
| 날짜·시간 | 기존 확정값 | 선택한 새 후보 |
| 참석자 | 기존 참석자 | 변경 후 참석자 |
| 응답 상태 | 기존 기록 | 새 후보 기준 |
| 외부 처리 | 기존 상태 | 변경 후 처리 예정 |

**E. 고정 CTA와 콘텐츠 겹침을 검증한다.**

현재 화면의 하단 고정 버튼과 긴 카드·변경 영향 안내가 겹치지 않도록 스크롤 여백을 확보한다.

### 6.4 권장 재조율 상태 모델

- `기존 회의 유지 중`
- `새 시간 조율 중`
- `응답 재확인 중`
- `새 후보 검토 중`
- `변경 확정 처리 중`
- `새 일정으로 변경 완료`
- `변경 실패 — 기존 일정 유지`
- `재조율 중단 — 기존 일정 유지`

변경 실패 시에는 실제 처리 결과에 따라 기존 일정 유지 여부를 확인해야 하며, 성공하지 않은 외부 캘린더 변경이나 알림을 완료로 표시해서는 안 된다.

## 7. 신규 기능 — 최근·자주 함께 회의한 참석자 추천

### 7.1 해결하려는 문제

현재 참석자 선택 흐름에서는 사용자가 회의를 만들 때마다 이름이나 팀으로 참석자를 다시 검색해야 할 수 있다.

반복적으로 같은 동료와 회의하는 사용자의 경우 이 과정이 불필요한 입력 부담이 된다.

### 7.2 추천하는 화면 구조

1. 참석자 선택 헤더 및 선택 인원
2. 이름·팀·이메일 검색
3. 팀 필터
4. 최근 함께 회의한 사람
5. 자주 함께 회의한 사람
6. 전체 참석자
7. 선택된 참석자 확인 및 다음 단계 CTA

### 7.3 추천 목록 정의

| 영역 | 초기 추천 정책 | 노출 수 |
|---|---|---|
| 최근 함께 회의한 사람 | NODI에 기록된 회의의 최근 순서 | 최대 5명 |
| 자주 함께 회의한 사람 | 최근 90일간 함께한 NODI 회의 횟수 | 최대 5명 |
| 전체 참석자 | 검색·팀 필터 기준 | 기존 목록 정책 유지 |

위 기간과 노출 인원은 초기 설계 가설이며, 사용자 검증 결과에 따라 조정한다.

### 7.4 추천 데이터 규칙

- 본인을 추천 대상에서 제외한다.
- 동일 인물을 두 추천 영역에 중복 노출하지 않는다.
- 최근 목록을 먼저 구성하고, 자주 목록은 중복 인원을 제외해 채운다.
- 동명이인은 이름 외에 팀·역할·이메일 등 식별 가능한 정보를 제공한다.
- 접근 권한이 없거나 비활성화된 사용자는 추천하지 않는다.
- 취소된 회의의 집계 여부를 명시적으로 정의한다.
- 실제 기록이 없으면 추천 목록을 임의로 생성하지 않는다.
- 외부 캘린더 기록은 실제 연동과 권한이 구현된 경우에만 활용한다.

### 7.5 선택 동작

- 추천 항목을 누르면 참석자 선택 상태에 반영한다.
- 전체 참석자 목록과 동일한 선택 상태를 공유한다.
- 추천 목록에서 선택 해제하면 전체 목록에도 반영한다.
- 검색 중에는 검색 결과를 우선 표시한다.
- 추천 항목은 자동으로 선택하지 않는다.
- 추천 인물을 자동으로 일정 필수 참석자로 지정하지 않는다.

### 7.6 빈 상태

최근 회의 기록이 없는 신규 사용자에게는 비어 있는 추천 영역을 보여주지 않는다.

권장 동작:

`전체 참석자` 목록을 바로 제공한다.

### 7.7 개인정보 및 설명 가능성

추천은 사용자의 회의 기록에 근거한 개인화 기능이다.

- 추천 기준을 짧게 안내한다.
- 다른 참석자에게 개인별 회의 빈도를 노출하지 않는다.
- 접근 가능한 회의 기록만 활용한다.
- 데이터 삭제 또는 접근 권한 변경을 반영한다.
- 조직 정책과 개인정보 보관 기준을 따른다.

### 7.8 후속 기능 제안

`지난 회의 참석자 다시 선택`

반복적인 디자인 리뷰나 팀 회의에서는 개인별 추천보다 이전 회의 참석자 그룹을 다시 불러오는 방식이 더 빠를 수 있다.

다만 그룹 일괄 선택 시에도 선택된 사람을 검토하고 수정할 수 있어야 한다.

**우선순위:** P1

### 8.2 모바일 화면 규칙

- 주요 CTA는 화면 하단에서 접근하기 쉽게 배치한다.
- CTA가 스크롤 콘텐츠를 가리지 않도록 하단 여백을 확보한다.
- iOS Safe Area를 반영한다.
- 키보드가 열리면 입력창과 주요 행동이 가려지지 않도록 한다.
- 전체 화면 시트와 모달의 스크롤 동작을 구분한다.
- Android 뒤로 가기와 iOS 뒤로 가기 동작을 검증한다.
- 로딩·실패·빈 상태에서 레이아웃이 크게 흔들리지 않도록 한다.

### 8.3 정보 위계

각 화면은 다음 순서를 우선한다.

**현재 상태 → 판단 근거 → 사용자의 다음 행동**

모든 정보를 한 카드에 넣기보다, 가장 중요한 판단 정보는 먼저 보여주고 세부 내용은 펼쳐서 확인하도록 한다.

### 8.4 후보 비교

모바일 비교 화면은 모든 속성을 동일한 비중으로 나열하지 않는다.

우선 비교할 정보:

1. 일정 필수 조건
2. 참석 가능·불가·미확인 인원
3. 선호 시간대 충족 여부
4. 후보 간 실제 차이
5. 추천 이유

점수는 상세 정보로 이동하거나 보조적으로 표시한다.

## 12. 사용성 검증 계획

정량 성과는 실제 측정 전까지 가설로 취급한다.

### 검증 과제 1 — 참석자 선택

**가설:** 최근·자주 함께 회의한 사람을 추천하면 반복적인 참석자 선택에 필요한 탐색 행동이 감소한다.

측정 항목:

- 참석자 선택 완료 시간
- 검색 사용 횟수
- 참석자 선택·해제 횟수
- 잘못 선택한 인원 수
- 과제 완료율

비교 조건:

- A: 검색과 전체 목록만 제공
- B: 최근·자주 추천 목록 추가

### 검증 과제 2 — 재조율 이해

**가설:** 기존 일정 유지와 새 후보 확정을 명확히 구분하면 사용자의 상태 오해가 감소한다.

확인 질문:

- 재조율을 시작하면 기존 회의가 취소된다고 생각하는가?
- 기존 참석 응답이 새 시간에도 유효하다고 생각하는가?
- 새 시간이 실제로 변경되는 시점을 이해하는가?

### 검증 과제 3 — 확정 상태 이해

**가설:** 내부 저장, 캘린더 반영, 알림 발송을 분리하면 회의 처리 결과에 대한 오해가 감소한다.

확인 질문:

- 이 회의는 NODI에 저장되었는가?
- 개인 캘린더에도 등록되었는가?
- 모든 참석자에게 알림이 전달되었는가?
- 참석자들이 모두 수락했는가?

실제 테스트에서 정답률, 오해 유형, 발화 내용을 기록한다.

## 13. Claude Code 개발 지시사항

### 개발 목표

기존 NODI의 브랜드와 주요 흐름을 유지하면서, 위 개선안을 실제 UI와 데이터 로직에 반영한다.

### 필수 지시

1. 기존 기능을 임의로 제거하지 않는다.
2. 기존 디자인 시스템과 NODI 로고를 유지한다.
3. 화면에 표시하는 모든 상태를 실제 데이터 모델과 연결한다.
4. 데모 기능을 실제 연동 기능처럼 표현하지 않는다.
5. 최근·자주 참석자 추천은 기록 기반으로 구현하고 가짜 기록을 생성하지 않는다.
6. 참석자 추천과 일정 필수 설정을 분리한다.
7. 재조율 시작 시 기존 회의를 취소하지 않는다.
8. 기존 응답 기록 보존과 새 후보 응답 유효성 판단을 분리한다.
9. 후보 선택 후 최종 변경 검토 단계를 제공한다.
10. 외부 처리 실패 시 실제 성공 여부를 확인하고 복구 경로를 제공한다.
11. iOS·Android 모바일 화면에서 키보드, 스크롤, 시트, 고정 CTA를 검증한다.
12. 화면 문구와 서버 상태가 불일치하지 않도록 테스트한다.

### 요청 산출물

- 개선된 화면 및 컴포넌트
- 상태 모델 변경 사항
- 최근·자주 참석자 추천 로직
- 재조율 후보별 응답 검증 로직
- 변경 전후 화면 비교
- 주요 QA 시나리오 및 테스트 결과
- 미구현·미검증 항목 목록

## 14. 최종 승인 기준

다음 조건이 충족되어야 이번 개선을 완료한 것으로 판단한다.

1. 사용자가 AI가 이해한 회의 조건을 확인하고 수정할 수 있다.
2. 참석자 선택과 일정 필수 지정이 명확히 분리된다.
3. 참석 가능, 응답 대기, 수락, 확정 상태가 혼용되지 않는다.
4. 회의 상세에서 내부 저장, 캘린더 반영, 알림 상태를 정확히 구분한다.
5. 재조율 중 기존 일정이 의도치 않게 취소되지 않는다.
6. 기존 응답을 새 후보에 잘못 재사용하지 않는다.
7. 실패한 알림을 안전하게 재시도할 수 있다.
8. 최근·자주 참석자 추천이 실제 접근 가능한 기록에 근거한다.
9. 추천 목록과 전체 참석자 목록의 선택 상태가 일치한다.
10. 모바일 주요 흐름에서 콘텐츠와 CTA가 겹치지 않는다.
11. 실제 구현되지 않은 기능을 완료된 것처럼 표현하지 않는다.
12. 실제 기기 및 사용자 테스트에서 발견한 문제를 기록하고 후속 조치한다.

## 15. 최종 제품 방향

NODI의 경쟁력은 AI가 회의 시간을 단순히 제안하는 데 있지 않다.

**사용자가 적은 입력으로 회의 조건을 정리하고, 참석자의 확인된 정보에 근거해 시간을 선택하며, 확정 이후 변경과 실패 상황까지 신뢰할 수 있게 관리하는 경험**이 핵심이다.

따라서 이번 개선은 다음 순서로 진행한다.

**정확한 상태 표현 → 안전한 확정·재조율 → 반복 작업 최소화 → 모바일 사용성 고도화**

최근·자주 함께 회의한 사람 추천은 이 중 반복 작업 최소화에 해당하는 기능이며, 핵심 상태·확정 로직을 해치지 않는 범위에서 도입한다.
