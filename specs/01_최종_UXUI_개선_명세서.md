# NODI 최종 UX/UI 개선 명세서

**권장 파일명:** `NODI_Final_UXUI_Improvement_Spec.md`  
**Version:** 1.0  
**기준:** NODI PRD v13.0 및 제공된 모바일 UI 7개 화면  
**대상:** Claude 기반 디자인·프런트엔드 개발  
**플랫폼:** Mobile-first Responsive Web · iOS · Android  
**디자인 방향:** Soft Clarity · Native-like UX

---

## 1. 프로젝트 목표

NODI는 AI와 대화하면서 회의 조건을 입력하고, 참석자의 일정 정보를 확인한 뒤 적합한 회의 시간을 추천받아 확정하는 서비스다.

현재 디자인은 브랜드 색상, 카드, 시트, 하단 내비게이션 등의 시각적 일관성이 확보되어 있다.

따라서 이번 개선 작업은 전면 재디자인이 아닌 **사용자 흐름과 상태 전달의 정확성을 높이는 작업**으로 진행한다.

### 핵심 목표

1. 사용자가 현재 어떤 단계에 있는지 이해할 수 있어야 한다.
2. AI가 해석한 조건과 사용자가 확정한 조건을 구분해야 한다.
3. 참석자의 일정 상태를 정확하게 전달해야 한다.
4. 추천 결과의 근거와 불확실성을 설명해야 한다.
5. 회의 조건 변경 후에도 데이터와 화면 상태가 일관되어야 한다.
6. 모바일 웹과 앱에서 키보드, 시트, 스크롤이 안정적으로 동작해야 한다.
7. 최종 회의 확정까지 끊김 없는 흐름을 제공해야 한다.

---

## 2. 반드시 유지할 디자인 요소

- 기존 NODI 공식 심볼 로고
- Soft Clarity 디자인 스타일
- 블루·퍼플 브랜드 컬러
- 라운드 카드 및 절제된 그림자
- 밝은 배경과 명확한 타이포그래피
- Lucide Outline 아이콘
- AI 대화와 구조화된 작업 UI의 결합
- iOS 스타일의 시트 및 내비게이션
- 3개 하단 탭: 회의 잡기 / 내 회의 / 받은 요청

기존 로고를 임의로 변경하거나 새로운 브랜드 심볼로 교체하지 않는다.

## 3. 최종 권장 사용자 흐름

```text
회의 잡기
   ↓
자연어로 회의 조건 입력
   ↓
AI 조건 해석
   ↓
조건 요약 및 확인
   ↓
참석자 선택
   ↓
필수 참석자 지정
   ↓
참석 가능 시간 확인
   ↓
추천 후보 생성
   ↓
후보 비교 및 선택
   ↓
최종 회의 정보 검토
   ↓
최신 상태 재검증
   ↓
회의 확정
   ↓
완료 화면 / 내 회의
```

### 흐름 설계 원칙

- AI는 자연어 이해와 설명을 담당한다.
- 참석자 선택, 날짜 변경, 후보 선택은 구조화된 UI로 처리한다.
- AI가 같은 질문을 반복하지 않는다.
- 사용자가 이전 단계로 돌아가도 입력한 값이 유지된다.
- 조건이 변경되면 영향을 받는 추천 결과를 다시 계산한다.
- 최종 확정은 명시적인 사용자 행동으로만 수행한다.

# 4. P0 — 반드시 개선해야 하는 UX

## P0-01. AI 대화와 작업 화면 연결

### 현재 문제

첫 화면에서 예시 문장을 선택한 뒤 조건 수정 및 참석자 선택 화면으로 이어지지만, AI가 입력을 어떻게 해석했는지 설명하는 연결 단계가 부족하다.

### 개선 요구사항

자연어 입력 후 AI가 추출한 조건을 구조화된 카드로 보여준다.

예시:

**AI 메시지**

"말씀하신 회의 조건을 정리했어요. 확인하고 참석자를 선택해 주세요."

**조건 요약 카드**

- 회의 종류: 디자인 리뷰
- 회의 길이: 60분
- 날짜: 11월 17일 화요일
- 선호 시간: 오후
- 참석자: 디자인팀 3명 선택 필요

**CTA**

- 보조: 조건 수정
- 주요: 참석자 선택

### 완료 기준

- 자연어에서 추출한 조건이 화면에 표시된다.
- 확인되지 않은 값은 확정된 것처럼 표시하지 않는다.
- 이미 추출된 조건을 AI가 반복해서 질문하지 않는다.
- 다음 행동이 명확하게 제시된다.

---

## P0-02. 날짜 및 시간 조건 선택 개선

### 현재 문제

조건 수정 화면에서 특정 주의 날짜만 표시되어 날짜 범위 지정이 어렵다.

### 개선 요구사항

다음 선택 방식을 지원한다.

- 특정 날짜 선택
- 날짜 범위 선택
- 이전·다음 주 탐색
- 달력에서 날짜 선택
- 오전 / 오후 / 상관없음
- 회의 길이 선택

상대 날짜는 실제 날짜로 변환해 표시한다.

예시:

"다음 주 화요일" → "11월 17일(화)"

단, 실제 날짜 계산은 사용자의 현재 날짜와 시간대를 기준으로 수행한다.

### 완료 기준

- 날짜 범위를 선택할 수 있다.
- 시간대와 회의 길이를 독립적으로 수정할 수 있다.
- 선택 상태가 시각적으로 명확하다.
- 기존에 입력한 다른 조건은 유지된다.

---

## P0-03. 참석자 선택과 필수 지정 구분

### 현재 문제

참석자 선택 화면에서 선택 상태와 필수 참석자 지정 상태가 함께 나타나 사용자가 두 기능을 혼동할 수 있다.

### 개선 요구사항

참석자 선택과 필수 지정은 서로 다른 의미를 갖도록 설계한다.

**참석자 선택**

- 회의에 포함할 사람을 선택한다.
- 다중 선택을 지원한다.
- 검색 및 팀 필터를 지원한다.
- 동명이인은 팀과 이메일로 구분한다.

**필수 참석자 지정**

- 선택된 참석자 중 반드시 일정 조건을 충족해야 하는 사람을 지정한다.
- 필수 지정은 참석 수락을 의미하지 않는다.
- 필수 지정된 참석자의 가용성은 추천 점수보다 우선한다.

### 권장 인터랙션

1. 참석자 선택
2. 선택 완료
3. 필수 참석자 지정
4. 다음 단계 이동

단계를 하나의 시트에서 처리하는 경우에도 제목과 컨트롤의 역할을 명확히 구분한다.

### 완료 기준

- 선택된 참석자 수가 정확하게 표시된다.
- 필터 변경 후에도 선택 상태가 유지된다.
- 선택하지 않은 사람을 필수 참석자로 지정할 수 없다.
- 필수 참석자의 의미를 이해할 수 있다.

---

## P0-04. 참석 가능 상태 정의 개선

### 현재 문제

참석 가능 시간 확인 화면에서 캘린더 정보와 실제 응답이 혼합되어 표시된다.

### 개선 요구사항

다음 상태를 구분한다.

| 상태 | 의미 |
|---|---|
| 일정 충돌 없음 | 캘린더에 등록된 충돌 일정이 없음 |
| 참석 가능 응답 | 참석자가 가능하다고 응답함 |
| 참석 불가 응답 | 참석자가 불가능하다고 응답함 |
| 일부 가능 | 지정된 후보 중 일부만 가능 |
| 응답 대기 | 아직 응답하지 않음 |
| 확인 불가 | 일정 정보를 조회할 수 없음 |

### 필수 규칙

- 일정 충돌 없음은 참석 수락이 아니다.
- 미응답은 참석 불가가 아니다.
- 확인 불가는 일정 충돌 없음으로 계산하지 않는다.
- 필수 참석자의 가용성은 별도로 강조한다.

### 권장 문구

기존:

"3명 · 확인 중 1명"

개선:

"3명 중 2명 일정 확인 · 1명 응답 대기"

단, 실제 데이터가 이 집계와 일치하는 경우에만 사용한다.

### 완료 기준

- 상태별 의미가 명확하다.
- 참석자별 정보 출처를 구분할 수 있다.
- 상태 집계가 실제 데이터와 일치한다.
- 추천 계산에 반영된 정보와 미확인 정보가 구분된다.

---

## P0-05. 추천 카드 신뢰성 개선

### 현재 문제

추천 화면에서 '모두 참석 가능', '확정 가능' 등의 표현이 실제 참석 응답이나 서버 검증 결과보다 강한 확신을 전달할 수 있다.

### 개선 요구사항

추천 카드는 다음 정보를 제공한다.

1. 추천 날짜와 시간
2. 회의 길이
3. 일정 조건 충족 인원
4. 필수 참석자 조건
5. 선호 시간 일치 여부
6. 미확인 정보
7. 추천 근거

### 추천 문구 원칙

검증 가능한 정보만 사용한다.

예시:

"3명의 일정 조건을 충족하는 후보예요. 다만 1명의 참석 응답은 아직 확인되지 않았어요."

### 추천 상태

- 추천 후보
- 필수 조건 충족
- 일부 참석자 불가
- 응답 대기
- 재확인 필요
- 확정 가능

'확정 가능'은 실제 확정 규칙을 통과한 경우에만 표시한다.

### 완료 기준

- 추천 점수와 확정 가능 여부를 구분한다.
- 동률 후보는 동률로 표시한다.
- 필수 참석자가 불가능한 후보는 추천 점수와 관계없이 제외한다.
- 미확인 정보가 숨겨지지 않는다.
- 추천 근거가 실제 데이터와 일치한다.

---

## P0-06. 조건 변경 시 추천 결과 무효화

### 문제 상황

사용자가 회의 길이를 60분에서 90분으로 변경했는데 이전 추천 결과가 그대로 남아 있으면 잘못된 후보를 선택할 수 있다.

### 개선 요구사항

다음 조건이 변경되면 추천 유효성을 재검증한다.

- 회의 날짜 또는 기간
- 회의 길이
- 선호 시간
- 참석자
- 필수 참석자
- 참석 가능 시간 데이터

### 상태 처리

```text
조건 변경
   ↓
기존 추천 무효화
   ↓
변경된 조건 저장
   ↓
추천 다시 계산
   ↓
새 추천 표시
```

### 완료 기준

- 오래된 추천으로 확정할 수 없다.
- 조건 변경 전 선택된 후보는 필요 시 해제된다.
- 재계산 중 로딩 상태가 표시된다.
- 재계산 실패 시 오류와 재시도 방법이 표시된다.

---

## P0-07. 모바일 키보드·시트·스크롤 안정성

### 개선 요구사항

**채팅 입력**

- iOS Safari 및 Android Chrome 지원
- 입력창이 키보드에 가려지지 않도록 처리
- 키보드 활성화 시 하단 Tab Bar 숨김
- 채팅 영역과 입력창의 스크롤 분리
- 사용자가 이전 메시지를 읽는 동안 강제 자동 스크롤 금지

**Bottom Sheet**

- Safe Area 적용
- 시트 내부 스크롤 지원
- 키보드가 열렸을 때 입력 필드 가시성 유지
- 배경 스크롤 차단
- 닫기 동작 시 작업 내용 보존 정책 정의

**고정 CTA**

- 화면 하단에 고정
- Safe Area를 고려한 여백
- 키보드와 겹치지 않음
- 비활성 상태에서도 버튼 라벨 가독성 확보

### 완료 기준

- 작은 화면에서도 주요 CTA가 잘리지 않는다.
- 키보드가 열려도 입력창을 사용할 수 있다.
- 시트와 배경이 동시에 스크롤되지 않는다.
- 뒤로 가기 동작이 일관된다.

---

## P0-08. 최종 검토·확정·완료 화면 추가

### 현재 문제

제공된 7개 화면에는 후보 선택 이후의 최종 확정 흐름이 나타나지 않는다.

### 추가 화면

**최종 검토**

- 회의 제목
- 날짜 및 시간
- 회의 길이
- 참석자
- 필수 참석자
- 미확인 정보
- 캘린더 및 초대 처리 예정 사항

**확정 처리**

- 최신 상태 재검증
- 중복 요청 방지
- 처리 중 상태
- 실패 및 재시도

**완료**

- NODI 내부 저장 상태
- 외부 캘린더 반영 상태
- 초대 발송 상태
- 내 회의로 이동

### 완료 기준

- 후보 선택만으로 회의가 확정되지 않는다.
- 사용자가 최종 정보를 확인하고 명시적으로 확정한다.
- 실패 시 중복 확정되지 않는다.
- 실제 완료된 작업만 성공으로 표시한다.

# 5. P1 — 사용성을 높이는 개선 사항

## P1-01. 추천 후보 비교 방식

모바일에서는 카드 뷰를 기본으로 제공한다.

비교표는 보조 기능으로 제공한다.

비교표에서는 다음 항목을 우선 강조한다.

- 참석 가능 인원
- 필수 참석자 충족 여부
- 불가능 인원
- 확인 중 인원
- 선호 시간 일치 여부

적합도 점수를 표시한다면 점수 산정 기준을 설명한다.

## P1-02. AI 메시지 간결화

AI는 한 번에 필요한 내용만 설명한다.

권장 구성:

- 현재 처리 결과
- 중요한 확인 사항
- 다음 행동

불필요하게 긴 설명은 작업 카드와 중복하지 않는다.

## P1-03. 진행 상태 안내

고정된 질문 번호 대신 현재 작업 단계를 표시한다.

예시:

- 회의 조건 확인
- 참석자 선택
- 가능 시간 확인
- 추천 시간 선택
- 최종 확인

AI 대화의 질문 수가 동적으로 달라지므로 '질문 1/8' 같은 표현은 사용하지 않는다.

## P1-04. 예외 상황 UX

다음 상황을 설계한다.

- 참석자가 검색되지 않음
- 동명이인 존재
- 선택된 참석자가 없음
- 추천 가능한 시간이 없음
- 필수 참석자 조건 충돌
- AI 조건 해석 실패
- 네트워크 연결 실패
- 확정 중 데이터 변경
- 외부 캘린더 연동 실패

각 상황에는 문제 설명과 사용자가 수행할 수 있는 다음 행동을 제공한다.

# 6. 디자인 시스템 적용 원칙

## 6.1 브랜드

- NODI 공식 심볼 유지
- 브랜드 블루·퍼플 유지
- Soft Clarity 스타일 유지
- AI 아바타와 브랜드 심볼 구분

## 6.2 타이포그래피

권장 기준:

- 화면 제목: 20–24px
- 섹션 제목: 18–20px
- 카드 제목: 16–18px
- 본문: 15–16px
- 보조 설명: 13–14px
- 채팅 입력: 최소 16px

실제 폰트 크기는 기기 및 접근성 설정에 따라 조정한다.

## 6.3 터치 영역

- 주요 터치 영역 최소 44×44pt 수준 확보
- 주요 CTA는 충분한 높이와 여백 확보
- 작은 아이콘은 터치 영역을 별도로 확장
- 선택 상태는 색상 외에도 체크·테두리·텍스트로 표현

## 6.4 버튼 상태

모든 주요 버튼은 다음 상태를 정의한다.

- Default
- Pressed
- Selected
- Disabled
- Loading
- Error
- Success

## 6.5 반응형 원칙

**모바일**

- 단일 컬럼
- 카드 기반 정보
- Bottom Sheet
- 주요 CTA 하단 배치

**태블릿**

- 넓어진 작업 영역
- 필요 시 2컬럼
- 시트 또는 다이얼로그 선택 적용

**데스크톱**

- 왼쪽 내비게이션
- 중앙 대화·작업 영역
- 오른쪽 조건 요약 패널
- 넓은 비교 테이블

# 10. Claude 개발 요청 최종 지침

현재 NODI의 브랜드 아이덴티티와 시각적 디자인은 유지해주세요.

이번 개선은 단순한 UI 리디자인이 아니라, 실제 사용자가 회의를 생성하고 확정하는 전체 UX 흐름을 완성하는 작업입니다.

다음 원칙을 반드시 지켜주세요.

1. 기존 NODI 로고와 디자인 시스템을 유지합니다.
2. 모바일 퍼스트로 구현하되 웹·iOS·Android 확장을 고려합니다.
3. AI 대화와 구조화된 작업 UI의 역할을 구분합니다.
4. 참석 가능 상태와 참석 수락 상태를 혼동하지 않습니다.
5. 필수 참석자 조건을 추천 점수보다 우선합니다.
6. 조건이 변경되면 기존 추천을 재검증합니다.
7. 최종 확정은 사용자 승인과 최신 데이터 검증 이후에만 수행합니다.
8. 실제 연동되지 않은 기능을 완료된 것처럼 표시하지 않습니다.
9. 화면뿐 아니라 상태 전이, 오류 처리, 뒤로 가기, 키보드 동작까지 구현합니다.
10. 기존 PRD와 충돌하는 요구사항이 있다면 임의로 결정하지 말고 변경 사항을 명시합니다.

## 요청 결과물

- 개선된 전체 사용자 흐름
- 기존 7개 화면 수정
- 최종 검토·확정·완료 화면 추가
- 컴포넌트별 인터랙션 및 상태 정의
- 모바일 웹·앱 반응형 명세
- 상태 전이 및 추천 재검증 로직
- 변경 사항 목록
- QA 체크리스트
- 구현 완료·미구현 기능 구분

**최종 목표:** 사용자가 AI의 안내를 이해하고, 정확한 일정 정보를 바탕으로 회의를 안전하게 확정할 수 있는 NODI를 완성합니다.
